### 1.2. Автогенерация первичных ключей: `GENERATED ALWAYS AS IDENTITY`

Стандарт SQL:2003, поддерживается PostgreSQL 10+. Преимущества:
- соответствует стандарту SQL;
- не создаёт «скрытую» отдельную sequence-таблицу, которой можно случайно манипулировать;
- запрещает явную вставку значения в столбец без `OVERRIDING SYSTEM VALUE` — защита от случайного перезаписывания PK.

**Синтаксис:**
```sql
CREATE TABLE region (
    region_id   INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    region_name VARCHAR(50) NOT NULL UNIQUE
);
```

**Параметры генерации:**
```sql
region_id BIGINT GENERATED ALWAYS AS IDENTITY
    (START WITH 1 INCREMENT BY 1 NO CYCLE) PRIMARY KEY
```

**Два режима:**

| Режим | Поведение |
|---|---|
| `GENERATED ALWAYS AS IDENTITY` | Значение задаётся только системой; явная вставка запрещена (кроме `OVERRIDING SYSTEM VALUE`). |
| `GENERATED BY DEFAULT AS IDENTITY` | Система подставляет значение, если пользователь не указал своё. |

**Пример явной вставки при `ALWAYS`:**
```sql
INSERT INTO region (region_id, region_name) OVERRIDING SYSTEM VALUE
VALUES (999, 'Custom Region');
```

> **Примечание.** Для «настоящих» справочных PK (например, `pokemon_national_dex_number`) автогенерация не нужна — это естественный ключ. `IDENTITY` уместен только для суррогатных ключей.

### 1.3. Ограничения целостности (constraints)

| Ограничение | Назначение | Пример |
|---|---|---|
| `PRIMARY KEY` | Уникально идентифицирует строку, не допускает `NULL` | `region_id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY` |
| `FOREIGN KEY` | Ссылка на строку в другой таблице | `FOREIGN KEY (region_id) REFERENCES region(region_id)` |
| `NOT NULL` | Запрещает пустые значения | `pokemon_name VARCHAR(50) NOT NULL` |
| `UNIQUE` | Запрещает дубликаты | `UNIQUE (pokemon_name)` |
| `CHECK` | Проверка условия на уровне строки | `CHECK (pokemon_base_hp >= 0)` |
| `DEFAULT` | Значение по умолчанию | `DEFAULT FALSE` |
| `ON DELETE CASCADE` | При удалении родителя удаляются дети | `ON DELETE CASCADE` |
| `ON DELETE SET NULL` | При удалении родителя FK становится `NULL` | `ON DELETE SET NULL` |
| `ON DELETE RESTRICT` | Запрещает удаление родителя, если есть дети | `ON DELETE RESTRICT` |

### 1.4. Правило именования столбцов: `сущность_поле`

Все столбцы именуются по шаблону **`<сущность>_<поле>`**:

- **Собственные атрибуты таблицы** префиксуются именем таблицы:
  `region_name`, `region_generation`, `pokemon_name`, `pokemon_base_hp`, `move_power`.
- **Первичный ключ** — `<имя_таблицы>_id`: `region_id`, `pokemon_id`, `trainer_id`.
- **Внешний ключ** — `<имя_ссылочной_сущности>_id`: `region_id`, `type_id`, `pokemon_id`.
- **Уточнённый FK** — если в таблице несколько ссылок на одну сущность, добавляется уточнение: `from_pokemon_id`, `to_pokemon_id`, `home_region_id`, `catch_region_id`.
- **Составной PK связочных таблиц** — это FK-столбцы, отдельного префикса не получают: `(pokemon_id, type_id)`, `(pokemon_id, ability_id)`.
- **Не ключевые столбцы связочных таблиц** — префиксуются именем связки: `pokemon_type_slot`, `pokemon_ability_is_hidden`.

### 1.5. Примеры первичных и внешних ключей

**PK с автогенерацией (суррогатный):**
```sql
CREATE TABLE trainer (
    trainer_id   INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    trainer_name VARCHAR(50) NOT NULL
);
```

**Естественный PK без автогенерации:**
```sql
CREATE TABLE language (
    language_code CHAR(2) PRIMARY KEY,
    language_name VARCHAR(50) NOT NULL
);
```

**Составной (композитный) PK:**
```sql
CREATE TABLE pokemon_type (
    pokemon_id INTEGER,
    type_id    INTEGER,
    PRIMARY KEY (pokemon_id, type_id)
);
```

**FK с каскадным удалением:**
```sql
CREATE TABLE pokemon_type (
    pokemon_id INTEGER REFERENCES pokemon(pokemon_id) ON DELETE CASCADE,
    type_id    INTEGER REFERENCES type(type_id)       ON DELETE RESTRICT
);
```

**FK, допускающий NULL (опциональная связь):**
```sql
region_id INTEGER REFERENCES region(region_id) ON DELETE SET NULL
```

> **Примечание.** `ON DELETE RESTRICT` — правильный выбор для справочников (типы, регионы): нельзя удалить тип, пока на него ссылаются покемоны. `CASCADE` — для «дочерних» таблиц (связки M:N, статы).

### 1.6. Прочие полезные приёмы

- **ENUM.** Удобен для фиксированных списков (пол, категория атаки).
  ```sql
  CREATE TYPE move_category AS ENUM ('physical', 'special', 'status');
  ```
- **CHECK.** Ограничения на диапазон значений.
  ```sql
  CHECK (pokemon_base_attack BETWEEN 0 AND 255)
  ```
- **TIMESTAMPTZ + DEFAULT NOW()** — стандарт для аудита создания записи.
- **JSONB** — для «гибких» характеристик (например, дополнительные статы или метаданные из API PokéAPI).

### 1.7. Как открыть терминал в Windows

Терминал понадобится для запуска Docker-команды. Подойдёт любой из вариантов:

1. **PowerShell (рекомендуется)**
   - Нажать `Win + X` → выбрать **Windows PowerShell** или **Терминал Windows**.
   - Либо `Win + R` → ввести `powershell` → `Enter`.

2. **Командная строка (cmd)**
   - `Win + R` → ввести `cmd` → `Enter`.
   - Или в поиске Пуск набрать `cmd` и открыть «Командная строка».

3. **Windows Terminal**
   - Установить из Microsoft Store → открыть через Пуск.
   - Позволяет держать несколько вкладок (PowerShell, cmd, WSL).

4. **Терминал из проводника**
   - Открыть папку с проектом → в адресной строке набрать `cmd` или `powershell` → `Enter`. Терминал откроется сразу в этой папке.

5. **Git Bash** (если установлен вместе с Git)
   - Правый клик в папке → **Git Bash Here**.

> **Примечание.** Docker-команда ниже — однострочная. В **cmd** перенос строки `\` не работает: пишите всё в одну строку без обратных слэшей. В **PowerShell** перенос строки — обратный апостроф `` ` ``; но проще тоже вводить одной строкой.

### 1.8. Развёртывание PostgreSQL в Docker и подключение через DBeaver

#### 1.8.1. Запуск контейнера

> **Важно.** Команду ниже нужно ввести **в терминале** (см. п. 1.7).

Одной строкой (подходит и для cmd, и для PowerShell):
```bash
docker run -d --name pokedex-pg -e POSTGRES_PASSWORD=pokedex_pass -p 5432:5432 postgres:latest
```

Образ `postgres:latest` — актуальная стабильная версия PostgreSQL (на момент написания — 17.x).

Из переменных окружения задаётся **только пароль** — `POSTGRES_PASSWORD`. Остальное image `postgres` подставляет по умолчанию:
- `POSTGRES_USER` = `postgres`;
- `POSTGRES_DB` = `postgres` (совпадает с `POSTGRES_USER`, если тот не переопределён).

#### 1.8.2. Проверка работы контейнера

```bash
docker ps
```
Контейнер `pokedex-pg` должен быть в статусе `Up`. Зайти в psql:
```bash
docker exec -it pokedex-pg psql -U postgres
# внутри psql:
#   \l            — список БД
#   \dt           — список таблиц
#   \q            — выход
```

#### 1.8.3. Подключение через DBeaver

1. **Database → New Database Connection** → выбрать **PostgreSQL** → **Next**.
2. Заполнить параметры:

   | Поле | Значение |
   |---|---|
   | Host | `localhost` |
   | Port | `5432` |
   | Database | `postgres` |
   | Username | `postgres` |
   | Password | `pokedex_pass` |
   | Save password | ✅ (по желанию) |

3. Вкладка **Driver properties** (обычно не требуется) — при необходимости:
   - `sslmode=disable` для локальной разработки;
   - `ApplicationName=PokedexDBeaver` для удобной идентификации в `pg_stat_activity`.
4. Нажать **Test Connection** → **Finish**.
5. Первое подключение предложит скачать JDBC-драйвер PostgreSQL — согласиться.

> **Примечание.** Если порт `5432` занят (например, локальным PostgreSQL), измените маппинг в `docker run` на `-p 5433:5432` и указывайте в DBeaver порт `5433`.

#### 1.8.4. Частые проблемы

| Проблема | Решение |
|---|---|
| `docker: command not found` | Docker Desktop не запущен / не в PATH → перезапустить Docker Desktop |
| `Connection refused` | Контейнер не запущен → `docker ps`; порт занят → сменить маппинг |
| `password authentication failed` | Проверить `POSTGRES_PASSWORD`; если пароль меняли — пересоздать контейнер (`docker rm -f pokedex-pg` и запустить заново) |
| DBeaver не видит драйвер | Manual driver download в окне подключения или `Help → Check for Updates` |

## ЧАСТЬ 2. ТЕХНИЧЕСКОЕ ЗАДАНИЕ

**СУБД:** PostgreSQL последней стабильной версии (образ `postgres:latest`, на момент написания — 17.x)
**Кодировка:** UTF-8
**Название БД:** `postgres` (или отдельная `pokedex`, создаваемая вручную после подключения)

### 2.1. Общее описание

База данных предназначена для хранения справочной информации о покемонах (виды, типы, способности, приёмы, эволюционные связи, регионы обитания), а также о тренерах и пойманных ими экземплярах покемонов. БД поддерживает каталогизацию, поиск и аналитику по игровым сущностям.

Сущности и связи:
- **Region 1 ── N Pokemon** (регион обитания)
- **Pokemon M ── N Type** (типы покемонов)
- **Pokemon M ── N Ability** (способности)
- **Pokemon M ── N Move** (возможные приёмы)
- **Pokemon 1 ── N Evolution** (эволюционные связи)
- **Trainer 1 ── N CaughtPokemon** (пойманные экземпляры)
- **Pokemon 1 ── N CaughtPokemon** (вид пойманного покемона)

Для всех суррогатных первичных ключей применяется `INTEGER GENERATED ALWAYS AS IDENTITY`. Все столбцы именуются по правилу **`<сущность>_<поле>`** (см. п. 1.4).

---

### 2.2. Описание таблиц

#### Таблица `region` — регионы
Справочник регионов (Kanto, Johto, Hoenn и т. д.).
- `region_id` — первичный ключ, `INTEGER GENERATED ALWAYS AS IDENTITY`.
- `region_name` — название региона, обязательное, уникальное, до 50 символов.
- `region_generation` — номер поколения (SMALLINT, ≥ 1).
- `region_description` — необязательное текстовое описание.

#### Таблица `type` — типы покемонов
Справочник стихий (Fire, Water, Grass и т. д.).
- `type_id` — первичный ключ, `INTEGER GENERATED ALWAYS AS IDENTITY`.
- `type_name` — название типа, обязательное, уникальное, до 30 символов.
- `type_color_hex` — цвет для UI в HEX (`#RRGGBB`), `CHAR(7)`.

#### Таблица `ability` — способности
Справочник способностей покемонов.
- `ability_id` — первичный ключ, `INTEGER GENERATED ALWAYS AS IDENTITY`.
- `ability_name` — название, обязательное, уникальное, до 60 символов.
- `ability_description` — текстовое описание эффекта.
- `ability_is_hidden` — признак скрытой способности (логическое, по умолчанию FALSE).

#### Таблица `move` — приёмы (атаки)
Справочник боевых приёмов.
- `move_id` — первичный ключ, `INTEGER GENERATED ALWAYS AS IDENTITY`.
- `move_name` — название, обязательное, уникальное, до 80 символов.
- `type_id` — FK на `type(type_id)`, обязательное, `ON DELETE RESTRICT`.
- `move_category` — категория (`physical` / `special` / `status`), обязательное.
- `move_power` — сила приёма (SMALLINT, 0…250), допускает NULL для статусных.
- `move_accuracy` — точность (SMALLINT, 0…100), допускает NULL.
- `move_pp` — количество использований (SMALLINT, 1…64).
- `move_description` — текстовое описание.

#### Таблица `pokemon` — виды покемонов
Основная справочная таблица.
- `pokemon_id` — первичный ключ, `INTEGER GENERATED ALWAYS AS IDENTITY`.
- `pokemon_national_dex_number` — номер в национальном Покедексе, обязательное, уникальное, > 0.
- `pokemon_name` — имя, обязательное, уникальное, до 50 символов.
- `pokemon_species` — биологический вид («Seed Pokémon» и т. п.), до 50 символов.
- `pokemon_height` — рост в метрах (NUMERIC(4,2)), ≥ 0.
- `pokemon_weight` — вес в кг (NUMERIC(5,2)), ≥ 0.
- `pokemon_base_hp`, `pokemon_base_attack`, `pokemon_base_defense`, `pokemon_base_sp_attack`, `pokemon_base_sp_defense`, `pokemon_base_speed` — базовые характеристики (SMALLINT, 1…255), обязательные.
- `pokemon_is_legendary` — логический, по умолчанию FALSE.
- `pokemon_is_mythical` — логический, по умолчанию FALSE.
- `region_id` — FK на `region(region_id)`, `ON DELETE SET NULL`.
- `pokemon_description` — текстовое описание вида.
- `pokemon_created_at` — `TIMESTAMPTZ`, по умолчанию текущий момент.

#### Таблица `pokemon_type` — связь M:N «покемон — тип»
У покемона может быть 1 или 2 типа.
- `pokemon_id` — FK на `pokemon(pokemon_id)`, `ON DELETE CASCADE`.
- `type_id` — FK на `type(type_id)`, `ON DELETE RESTRICT`.
- `pokemon_type_slot` — порядковый номер типа (1 или 2).
- Первичный ключ — составной (`pokemon_id`, `type_id`); без автогенерации.
- Уникальность (`pokemon_id`, `pokemon_type_slot`).

#### Таблица `pokemon_ability` — связь M:N «покемон — способность»
- `pokemon_id` — FK на `pokemon(pokemon_id)`, `ON DELETE CASCADE`.
- `ability_id` — FK на `ability(ability_id)`, `ON DELETE RESTRICT`.
- `pokemon_ability_is_hidden` — логическое.
- `pokemon_ability_slot` — порядковый номер.
- Составной первичный ключ (`pokemon_id`, `ability_id`); без автогенерации.

#### Таблица `pokemon_move` — связь M:N «покемон — приём»
- `pokemon_id` — FK на `pokemon(pokemon_id)`, `ON DELETE CASCADE`.
- `move_id` — FK на `move(move_id)`, `ON DELETE CASCADE`.
- `pokemon_move_learn_method` — способ изучения (`level-up`, `tm`, `egg`, `tutor`), до 20 символов.
- `pokemon_move_level_learned` — уровень изучения (SMALLINT, 1…100), допускает NULL.
- Составной первичный ключ (`pokemon_id`, `move_id`, `pokemon_move_learn_method`); без автогенерации.

#### Таблица `evolution` — эволюционные связи
Связывает виды покемонов по линии эволюции.
- `evolution_id` — первичный ключ, `INTEGER GENERATED ALWAYS AS IDENTITY`.
- `from_pokemon_id` — FK на `pokemon(pokemon_id)`, `ON DELETE CASCADE`.
- `to_pokemon_id` — FK на `pokemon(pokemon_id)`, `ON DELETE CASCADE`.
- `evolution_trigger` — условие эволюции (`level-up`, `trade`, `item`, `friendship`), до 30 символов.
- `evolution_min_level` — минимальный уровень (SMALLINT, 1…100), NULL если неприменимо.
- `evolution_item_name` — имя предмета-триггера (до 50 символов), NULL если неприменимо.
- Ограничение: `from_pokemon_id <> to_pokemon_id`.
- Уникальность пары (`from_pokemon_id`, `to_pokemon_id`).

#### Таблица `trainer` — тренеры
- `trainer_id` — первичный ключ, `INTEGER GENERATED ALWAYS AS IDENTITY`.
- `trainer_name` — имя, обязательное, до 50 символов.
- `trainer_email` — email, уникальное, до 120 символов.
- `home_region_id` — FK на `region(region_id)`, `ON DELETE SET NULL`.
- `trainer_registered_at` — `TIMESTAMPTZ`, по умолчанию текущий момент.

#### Таблица `caught_pokemon` — пойманные экземпляры
Конкретные особи покемонов у тренеров (не виды, а индивиды).
- `caught_pokemon_id` — первичный ключ, `INTEGER GENERATED ALWAYS AS IDENTITY`.
- `trainer_id` — FK на `trainer(trainer_id)`, `ON DELETE CASCADE`.
- `pokemon_id` — FK на `pokemon(pokemon_id)`, `ON DELETE RESTRICT`.
- `caught_pokemon_nickname` — кличка (до 50 символов), необязательна.
- `caught_pokemon_level` — уровень (SMALLINT, 1…100), обязательное.
- `caught_pokemon_gender` — пол (`M`, `F`, `N`), необязательное.
- `caught_pokemon_is_shiny` — логическое, по умолчанию FALSE.
- `caught_pokemon_catch_date` — дата поимки, по умолчанию текущая дата.
- `catch_region_id` — FK на `region(region_id)`, `ON DELETE SET NULL`.

### 2.3. Требования к целостности

1. **Именование столбцов — по правилу `<сущность>_<поле>`** (см. п. 1.4):
   - собственные атрибуты префиксуются именем таблицы (`pokemon_name`, `move_power`);
   - PK именуется `<таблица>_id`;
   - FK именуется `<ссылочная_сущность>_id` (при нескольких ссылках на одну сущность — с уточнением: `from_pokemon_id`, `to_pokemon_id`);
   - неключевые столбцы связочных таблиц префиксуются именем связки (`pokemon_type_slot`).
2. Все суррогатные PK объявляются как `INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY` (или `BIGINT` при ожидании роста свыше 2 млрд записей).
3. Связочные таблицы (`pokemon_type`, `pokemon_ability`, `pokemon_move`) используют **составной** первичный ключ без автогенерации.
4. Все FK сопровождаются политиками `ON DELETE`:
   - `CASCADE` — для связочных и дочерних таблиц;
   - `RESTRICT` — для справочников, используемых в связях;
   - `SET NULL` — для необязательных атрибутов (регион, кличка).
5. Все обязательные поля помечены `NOT NULL`.
6. Бизнес-инварианты реализуются через `CHECK`:
   - характеристики покемонов в диапазоне 1…255;
   - уровень экземпляра в диапазоне 1…100;
   - рост и вес ≥ 0;
   - `from_pokemon_id <> to_pokemon_id`.
7. Уникальность: `region_name`, `type_name`, `ability_name`, `move_name`, `pokemon_name`, `pokemon_national_dex_number`, `trainer_email`.

### 2.4. Результат работы

Скрипт `schema.sql`, содержащий:
1. `CREATE TYPE` для пользовательских перечислений (`move_category`, `gender`);
2. `CREATE TABLE` для всех 11 таблиц с ограничениями, `IDENTITY`-столбцами и именами по правилу `<сущность>_<поле>`;
3. `INSERT`-скрипты первичного наполнения справочников (`region`, `type`).
