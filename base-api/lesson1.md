## Лабораторная работа: Проектирование сущностей для базы данных «Покемоны»
Цель задания: Спроектировать объектно-ориентированную модель данных на языке C# и настроить связи между сущностями с использованием атрибутов данных (Data Annotations).Модель строится на основе структуры данных PokeAPI.
------------------------------
## 1. Описание предметной области
Информационная система собирает и структурирует данные о вымышленных существах — Покемонах, их стихийных типах, пассивных способностях и боевых характеристиках.
## Основные сущности и их структура:

* Покемон (Pokemon)
  Главная сущность системы.
* Свойства: Уникальный числовой идентификатор (ID из PokeAPI), текстовое имя (обязательное, максимум 100 символов), рост (в дециметрах), вес (в гектограммах) и базовый опыт (целое число).
    * Связи: Связан с типами, способностями и характеристиками через промежуточные сущности.
* Тип покемона (Type)
  Стихийная принадлежность существа (например: Огненный, Водный, Травяной).
* Свойства: Идентификатор (автоинкремент), название типа (обязательное, уникальное, максимум 50 символов).
    * Связи: Отношение «многие-ко-многим» с покемонами. Так как в базе данных необходимо хранить дополнительное свойство для этой связи (номер слота), она реализуется через явную промежуточную сущность PokemonType.
* Промежуточная сущность: Тип покемона в слоте (PokemonType)
  Связующая таблица для Pokemon и Type. У покемона может быть до двух типов: основной и вторичный.
* Свойства: Порядковый номер слота (Slot: принимает значения 1 или 2, обязательное поле).
    * Связи: Содержит составной первичный ключ и навигационные свойства на Pokemon и Type.
* Способность (Ability)
  Уникальное пассивное умение покемона, автоматически срабатывающее в бою (например: Overgrow).
* Свойства: Идентификатор (автоинкремент), название (обязательное, максимум 100 символов) и краткое описание эффекта (текст неограниченной длины).
    * Связи: Отношение «многие-ко-многим» с покемонами через промежуточную сущность PokemonAbility.
* Промежуточная сущность: Способность конкретного покемона (PokemonAbility)
  Связующая таблица для Pokemon и Ability. Отражает, какими умениями обладает конкретный вид покемона.
* Свойства: Логический флаг IsHidden (Скрытая способность). Он равен true, если способность является редкой/альтернативной для этого покемона, и false, если она обычная.
    * Связи: Содержит составной первичный ключ и навигационные свойства на Pokemon и Ability.
* Характеристика (Stat)
  Справочник из 6 фиксированных системных параметров боевой силы (HP, Attack, Defense, Special Attack, Special Defense, Speed).
* Свойства: Идентификатор (автоинкремент) и название характеристики (обязательное, максимум 50 символов).
    * Связи: Отношение «многие-ко-многим» с покемонами через промежуточную сущность PokemonStat.
* Промежуточная сущность: Значение характеристики покемона (PokemonStat)
  Связующая таблица, которая задает конкретные числовые параметры для каждого покемона.
* Свойства: Числовое значение (BaseStat), определяющее силу конкретного параметра у данного покемона (обязательное целое число).
    * Связи: Содержит составной первичный ключ и навигационные свойства на Pokemon и Stat.

## 2. Технические требования к реализации

1. Использование Data Annotations: Для конфигурации моделей разрешено использовать исключительно атрибуты данных из пространств имен System.ComponentModel.DataAnnotations, System.ComponentModel.DataAnnotations.Schema и Microsoft.EntityFrameworkCore. Конфигурация через Fluent API (OnModelCreating) в рамках данного задания запрещена.
2. Навигационные свойства: Каждая сущность должна содержать корректные навигационные свойства: одиночные свойства для связей «к одному» и коллекции (ICollection<T>) для связей «ко многим».
3. Правила именования: Код должен соответствовать гайдлайнам C# (классы и свойства в PascalCase, внешние ключи вида СущностьId). Имена таблиц в базе данных должны быть явно указаны во множественном числе (например, Pokemons, Types).

------------------------------
## 3. Методическая справка по Data Annotations в EF Core 10## Ключи и идентификаторы

* [Key] — указывает на одиночный первичный ключ таблицы. По умолчанию для типа int EF Core делает его автоинкрементным (Identity).
* [DatabaseGenerated(DatabaseGeneratedOption.None)] — отключает автоматическую генерацию чисел (автоинкремент) для первичного ключа. Это необходимо для сущности Pokemon, так как его Id — это фиксированный номер, который мы вручную забираем из внешней системы (PokeAPI).
* [PrimaryKey(nameof(Prop1), nameof(Prop2))] — (Важно для EF Core 10!) Этот атрибут ставится строго над классом и используется для создания составных первичных ключей в промежуточных таблицах Many-to-Many. Использовать [Key] на нескольких свойствах внутри одного класса в EF 10 запрещено.

## Ограничения полей

* [Required] — указывает, что поле обязательно для заполнения (NOT NULL в базе данных). Обязательно к применению для строковых полей (например, Name), иначе EF Core 10 при включенном nullable в проекте может сделать их необязательными колонками (NULL).
* [MaxLength(X)] — задает максимальную длину строкового поля в символах. В базе данных это свойство превратится в тип VARCHAR(X) или NVARCHAR(X) вместо тяжелого TEXT / MAX.

## Настройка связей и схемы

* [Table("TableName")] — явно задает имя таблицы в базе данных.
* [ForeignKey("IdName")] — связывает навигационное свойство (объект) с полем внешнего ключа в таблице. Например, вешается над свойством public Pokemon Pokemon { get; set; }, чтобы указать, что за него отвечает колонка PokemonId.

## 4. Эталонный пример реализации связующей сущности
Используйте данный шаблон в качестве образца для проектирования промежуточных сущностей с составными ключами в EF Core 10:
```
using System.ComponentModel.DataAnnotations;
using System.ComponentModel.DataAnnotations.Schema;
using Microsoft.EntityFrameworkCore; 
// Необходим для работы [PrimaryKey]
namespace PokemonApi.Models;
// 1. Указываем составной первичный ключ из двух ID прямо над классом
[Table("PokemonTypes")]
[PrimaryKey(nameof(PokemonId), nameof(TypeId))] public class PokemonType
{
// Внешний ключ на Покемона
public int PokemonId { get; set; }

    // Внешний ключ на Тип
    public int TypeId { get; set; }

    // Дополнительное свойство связи (номер слота: 1 или 2)
    [Required]
    public int Slot { get; set; }

    // Навигационные свойства с явным указанием внешних ключей
    [ForeignKey(nameof(PokemonId))]
    public virtual Pokemon Pokemon { get; set; } = null!;

    [ForeignKey(nameof(TypeId))]
    public virtual Type Type { get; set; } = null!;
}
```
