## Тема: Первый REST API на C#. Minimal API в Rider, OpenAPI и тестирование через Bruno

## 1. Краткие теоретические сведения

### 1.1. Что такое API и зачем он нужен

API (Application Programming Interface) — это **контракт** между двумя программами. Одна программа (клиент) говорит: «дай мне вот это», другая (сервер) отвечает: «держи, вот твой JSON». Клиент не лезет внутрь сервера, не знает, где там база данных и как она устроена. Ему важен только контракт.

Аналогия: **API — это официант в ресторане**. Ты (клиент) не заходишь на кухню и не готовишь сам. Ты говоришь официанту: «Принеси пасту карбонара». Официант идёт на кухню (сервер), возвращается и приносит результат. Если пасты нет — возвращается с сообщением «нет такого блюда». Всё общение — по понятным правилам.

Правила этого общения в вебе называются **HTTP** и **REST**.

### 1.2. HTTP-методы: язык API

Каждый запрос к API содержит **метод** — глагол, который говорит, что мы хотим сделать.

| Метод | Что делает | Пример |
|-------|------------|--------|
| `GET` | Получить данные | Список покемонов, один покемон по id |
| `POST` | Создать новый ресурс | Добавить покемона в покедекс |
| `PUT` | Полностью заменить ресурс | Перезаписать покемона по id |
| `PATCH` | Частично обновить | Изменить только уровень |
| `DELETE` | Удалить | Убрать покемона из покедекса |

Важно: **метод — это часть контракта**. Если ты хочешь что-то создать — это всегда `POST`, а не `GET`. Даже если очень хочется.

### 1.3. Коды ответов: что сервер говорит клиенту

Каждый ответ содержит **код** — короткое число, которое говорит, всё ли прошло хорошо.

- **2xx — успех:**
    - `200 OK` — всё хорошо, вот данные.
    - `201 Created` — новый ресурс создан (обычно после `POST`).
    - `204 No Content` — всё ок, но возвращать нечего (например, после `DELETE`).
- **4xx — ошибка клиента:**
    - `400 Bad Request` — ты прислал что-то не то (невалидные данные).
    - `401 Unauthorized` — ты не авторизован.
    - `403 Forbidden` — ты авторизован, но тебе нельзя.
    - `404 Not Found` — такого ресурса нет.
- **5xx — ошибка сервера:**
    - `500 Internal Server Error` — что-то упало у нас, не у тебя.

**Правило:** клиент виноват — `4xx`, сервер виноват — `5xx`. Если ты не уверен, чей код использовать — почти всегда это `400` или `404`.

### 1.4. Как возвращать статусы в Minimal API

В Minimal API для возврата статуса используется статический класс **`Results`**. Каждый метод возвращает объект `IResult`, который ASP.NET Core превращает в HTTP-ответ.

| Метод | Что возвращает | Когда использовать |
|-------|---------------|---------------------|
| `Results.Ok(data)` | 200 OK + тело | Успешный `GET`, `PUT` |
| `Results.Created(uri, data)` | 201 Created + заголовок `Location` + тело | Успешный `POST` |
| `Results.NoContent()` | 204 No Content без тела | Успешный `DELETE` |
| `Results.NotFound()` | 404 Not Found | Ресурса нет |
| `Results.BadRequest(data)` | 400 Bad Request + тело | Невалидные данные |
| `Results.Problem(...)` | 500 / другое | Ошибка сервера |

**Важно:** если ты просто возвращаешь объект (`return pokemon;`), ASP.NET Core обернёт его в `200 OK`. Но если возможен не только успех — возвращай `IResult` явно, чтобы контролировать код ответа.

```csharp
// Плохо: вернётся 200 с null, если не нашли
app.MapGet("/pokemons/{id}", (int id) =>
    pokemons.FirstOrDefault(p => p.Id == id));

// Хорошо: явно контролируем код через тернарный оператор
app.MapGet("/pokemons/{id}", (int id) =>
{
    var pokemon = pokemons.FirstOrDefault(p => p.Id == id);
    return pokemon is null
        ? Results.NotFound()
        : Results.Ok(pokemon);
});
```

### 1.5. Minimal API: минимум кода — максимум дела

```csharp
var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

app.MapGet("/hello", () => "Привет, мир API!");

app.Run();
```

Три строки — и у тебя работает HTTP-сервер.

### 1.6. OpenAPI: контракт, из которого рождаются запросы

**OpenAPI** — это спецификация, которая описывает HTTP API в формате JSON. (Swagger — старое название OpenAPI, но мы будем использовать современный термин.) ASP.NET Core генерирует её прямо из кода.

Ключевая идея лабораторной: **OpenAPI — источник истины**. Ты пишешь код — OpenAPI автоматически описывает эндпоинты. Дальше документ импортируется в Bruno, и ты получаешь готовую коллекцию запросов **без ручного ввода URL и тела**.

**В .NET 10** OpenAPI встроен в шаблон `webapi`. Документ доступен по адресу:

```
https://localhost:5001/openapi/v1.json
```

Для удобного просмотра можно поставить **Scalar** — бесплатный OpenAPI-визуализатор без регистрации:

```
https://localhost:5001/scalar/v1
```

Но главный инструмент в этой лабе — **импорт OpenAPI в Bruno**.

### 1.8. CRUD и HTTP

| CRUD | HTTP | Пример маршрута | Типичный код ответа |
|------|------|-----------------|---------------------|
| **C**reate | POST | `/pokemons` | 201 Created |
| **R**ead (все) | GET | `/pokemons` | 200 OK |
| **R**ead (одно) | GET | `/pokemons/{id}` | 200 OK или 404 |
| **U**pdate | PUT | `/pokemons/{id}` | 200 OK или 204 |
| **D**elete | DELETE | `/pokemons/{id}` | 204 или 404 |

Запомни это как таблицу умножения — она всплывёт на каждом собеседовании.

### 1.9. Частая ошибка новичка

Использовать `GET` для всего. «Хочу удалить — сделаю `GET /deletePokemon?id=1`». Так делать **нельзя**. Метод — часть контракта, и клиенты (браузеры, HTTP Client, чужие программы) ожидают, что `GET` — безопасный и не меняет данные, а `DELETE` — меняет. Если нарушаешь правило, ломаются кэши, браузеры, прокси и весь веб.

Второй частый промах — возвращать `200 OK` на любую ошибку с текстом «not found» в теле. Так нельзя: код ответа — часть контракта. Не нашёл — `404`. Невалидные данные — `400`. Сервер упал — `500`.

### 1.10. Как выбрать код ответа за 5 секунд

1. **Всё прошло, данные есть?** → `Results.Ok(data)` (200).
2. **Создал что-то новое?** → `Results.Created(uri, data)` (201).
3. **Удалил, возвращать нечего?** → `Results.NoContent()` (204).
4. **Не нашёл ресурс?** → `Results.NotFound()` (404).
5. **Клиент прислал мусор?** → `Results.BadRequest(errors)` (400).
6. **Что-то сломалось у меня?** → `Results.Problem(...)` (500).

## Часть 1. Bruno и PokeAPI

**Формулировка задачи:** научиться отправлять HTTP-запросы через Bruno, читать ответы, понимать коды, сохранять запросы в коллекцию. В качестве источника данных используем **PokeAPI** — открытый API с информацией о покемонах.

### Техническое задание:

1. **Установи Bruno** с сетевого диска (путь уточни у преподавателя). Регистрация не требуется.

2. Создай новую **коллекцию** с названием `Lab1 — PokeAPI`. Bruno создаст папку на диске, где будут храниться все запросы как обычные файлы. Сохрани коллекцию в свою рабочую папку.

3. Выполни **шесть запросов** и сохрани их в коллекцию. Все запросы к PokeAPI — это `GET`, так как API работает только на чтение (consumption-only API). Один запрос — `POST` к jsonplaceholder — нужен, чтобы увидеть, как выглядит создание ресурса и код `201 Created`.

   **3.1. Получить покемона по имени** (GET):
   ```
   GET https://pokeapi.co/api/v2/pokemon/pikachu
   ```
   Ожидаемый код: `200 OK`. Тело: JSON с полями `name`, `id`, `types`, `abilities`, `stats`, `sprites` и другими. Обрати внимание на массив `types` — там указан тип покемона (electric).

   **3.2. Получить покемона по id** (GET):
   ```
   GET https://pokeapi.co/api/v2/pokemon/25
   ```
   Ожидаемый код: `200 OK`. Тело: тот же JSON, что и в 3.1 (Pikachu имеет id = 25). Это показывает, что PokeAPI принимает и имя, и числовой id.

   **3.3. Получить список покемонов с пагинацией** (GET):
   ```
   GET https://pokeapi.co/api/v2/pokemon?limit=5&offset=0
   ```
   Ожидаемый код: `200 OK`. Тело: JSON с полем `results` — массив из пяти объектов `{ "name": "...", "url": "..." }`. Это пример **query-параметров**: `limit` и `offset` управляют размером страницы.

   **3.4. Получить информацию о типе** (GET):
   ```
   GET https://pokeapi.co/api/v2/type/electric
   ```
   Ожидаемый код: `200 OK`. Тело: JSON с полями `name`, `damage_relations` (уязвимости и сильные стороны), `pokemon` (список покемонов этого типа).

   **3.5. Создать пост** (POST) — к jsonplaceholder:
   ```
   POST https://jsonplaceholder.typicode.com/posts
   Content-Type: application/json

   {
     "title": "Мой первый покемон",
     "body": "Поймал Пикачу!",
     "userId": 1
   }
   ```
   Ожидаемый код: `201 Created`. Обрати внимание на заголовок `Location` в ответе — там адрес нового ресурса. PokeAPI не поддерживает POST, поэтому для демонстрации создания ресурса используем jsonplaceholder — это учебный сервис.

   **3.6. Сломанный запрос** (GET):
   ```
   GET https://pokeapi.co/api/v2/pokemon/unknown-pokemon-xyz
   ```
   Ожидаемый код: `404 Not Found`. Это учебная ошибка — так ты увидишь, как выглядит «ресурса нет» в PokeAPI.

4. Для **каждого** запроса в коллекции:
    - дай осмысленное имя (например, «Покемон по имени», «Список покемонов», «Создать пост»);
    - в описании напиши, что делает запрос и какой код ожидается.

5. Дополнительно (бонус к оценке): сделай запрос с **query-параметром** для фильтрации:
   ```
   GET https://pokeapi.co/api/v2/pokemon?limit=3&offset=10
   ```
   Сохрани его тоже. Обрати внимание: тот же эндпоинт, но другой `offset` — другой набор покемонов.

6. **Экспортируй коллекцию**: правой кнопкой на коллекцию → `Export` → формат `Bruno Collection` (или `Postman Collection`). Сохрани файл как `pokeapi.bruno.json`.

### Требуемый результат:

Файл с экспортированной коллекцией, содержащий **шесть** запросов (5 обязательных + 1 бонусный). Каждый запрос имеет имя, описание и сохранён в правильной папке (например, `Pokemon`, `Types`, `Posts`).

**Свобода:** можешь заменить некоторые эндпоинты PokeAPI на другие из документации (https://pokeapi.co/docs/v2) — например, `/berry/1`, `/ability/limber`, `/evolution-chain/1`. Главное — минимум 5 запросов к PokeAPI, минимум 1 `POST` к jsonplaceholder, минимум 1 запрос с кодом `404`.

    var existing = pokemons.FirstOrDefault(p => p.Id == id);

    // TODO 1: если existing == null — верни 404.
    //         Подсказка: Results.NotFound()

    pokemons.Remove(existing);

**Проверь себя по таблице:**

| Ситуация | Ожидаемый код | Какой метод `Results` |
|----------|--------------|----------------------|
| `POST` успешно | 201 + Location | `Results.Created(...)` |
| `POST` с мусором | 400 | `Results.BadRequest(...)` |
| `PUT` обновил | 200 | `Results.Ok(...)` |

| `PUT` с мусором | 400 | `Results.BadRequest(...)` |
| `DELETE` удалил | 204 | `Results.NoContent()` |
| `DELETE` не нашёл | 404 | `Results.NotFound()` |

**Важно:** при `POST` id генерируется автоматически (`max(id) + 1`). Клиент его не присылает — поэтому для входных данных отдельный тип `PokemonInput` без поля `Id`.

### Шаг 6. Тестирование через Bruno через импорт OpenAPI

Это ключевой шаг. Мы **не пишем запросы вручную** — мы берём OpenAPI-документ, который сгенерировал ASP.NET Core, и импортируем его в Bruno. Bruno сам построит коллекцию со всеми эндпоинтами, правильными методами, URL и типами тела.

#### 6.1. Убедись, что API запущен

Проект должен быть запущен (зелёный треугольник). Проверь в браузере, что OpenAPI доступен:

```
https://localhost:5001/openapi/v1.json
```

Ты должен увидеть JSON-документ со всеми своими эндпоинтами.

> **Важно про HTTPS и сертификат.** Bruno при первом запросе к `https://localhost:5001` может ругаться на самоподписанный сертификат. В настройках Bruno (`Preferences → General`) отключи проверку SSL для локальной разработки, либо используй `http://localhost:5000` — этот порт работает без сертификата.

#### 6.2. Импортируй OpenAPI в Bruno

1. Открой Bruno (запусти установленный ярлык).
2. `Collection → Import Collection` (или значок «Import» на стартовом экране).
3. Выбери тип **OpenAPI V3 Spec**.
4. Укажи:
   - **URL:** `https://localhost:5001/openapi/v1.json`
   - либо скачай файл и укажи **File** — путь к `v1.json`.

   Импорт по URL удобнее: если изменишь API — просто переимпортируешь.

5. Назови коллекцию `PokedexApi`.
6. Нажми **Import**.

Bruno создаст коллекцию, в которой уже есть **все твои эндпоинты**, сгруппированные по путям:

- `GET /hello`
- `GET /pokemons`
- `GET /pokemons/{id}`
- `POST /pokemons`
- `PUT /pokemons/{id}`
- `DELETE /pokemons/{id}`

У каждого запроса уже проставлены метод, URL, ожидаемые коды ответов и (если OpenAPI знает схему) шаблон тела для `POST`/`PUT`.

#### 6.3. Настрой базовый URL

1. Открой любой запрос в коллекции.
2. Справа увидишь переменные окружения. Создай окружение `local`:
   - `baseUrl = https://localhost:5001` (или `http://localhost:5000`, если без HTTPS).
3. В URL запроса замени `{{baseUrl}}` на свою переменную, если Bruno не сделал это автоматически.

#### 6.4. Прогони все запросы

Проверь **каждый** эндпоинт:

1. **`GET /hello`** → ожидаем `200 OK`, тело `"Привет, мир API!"`.
2. **`GET /pokemons`** → ожидаем `200 OK`, массив из трёх покемонов.
3. **`GET /pokemons/1`** → ожидаем `200 OK`, покемон `Pikachu`.
4. **`GET /pokemons/999`** → ожидаем `404 Not Found`. (Измени путь вручную, если в коллекции только `/pokemons/{id}` с параметром.)
5. **`POST /pokemons`** → тело:
   ```json
   { "name": "Bulbasaur", "type": "Grass", "level": 6 }
   ```
   Ожидаем `201 Created` и заголовок `Location: /pokemons/4`.
6. **`PUT /pokemons/2`** → тело:
   ```json
   { "name": "Charmeleon", "type": "Fire", "level": 16 }
   ```
   Ожидаем `200 OK` с обновлённым объектом.
7. **`DELETE /pokemons/3`** → ожидаем `204 No Content`.
8. **`POST /pokemons`** с мусором:
   ```json
   { "name": "X", "type": "Rock", "level": 999 }
   ```
   Ожидаем `400 Bad Request` с массивом ошибок.

#### 6.5. Сохрани коллекцию и экспортируй

1. Сохрани коллекцию (`Ctrl+S`).
2. Правой кнопкой на коллекцию `PokedexApi` → `Export` → формат `Bruno Collection`.
3. Сохрани файл как `pokedex-api.bruno.json` в свою рабочую папку.

Это и есть твой результат по части 2 вместе с проектом.

### Шаг 7 (бонус к оценке). Проверка, что импорт обновляется

1. Добавь в API ещё один эндпоинт `GET /pokemons/type/{type}` — возвращает покемонов указанного типа. **Напиши его сам** по аналогии с `GET /pokemons/{id}`.

Это демонстрирует главную идею лабораторной: **код → OpenAPI → Bruno**, контракт живёт вместе с кодом.
