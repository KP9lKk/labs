# Лабораторная работа №1: Разбор байт-кода JVM

## Зачем это нужно

Вы пишете код на Kotlin. Компилятор превращает его в байт-код. JVM превращает байт-код в машинные инструкции. Где-то в этой цепочке ваша программа перестаёт быть текстом и становится тем, что реально выполняется.

Эта лабораторная — про то, чтобы увидеть промежуточный этап. Не потому что «так надо», а потому что без этого невозможно:

- понимать, почему один код быстрее другого;
- читать чужой скомпилированный код (реверс-инжиниринг — реальная задача);
- понимать, что делает JIT-компилятор, когда оптимизирует ваш метод;
- отвечать на вопросы на собеседованиях про JVM.

---

## Что вы будете делать

Исследовать байт-код JVM на нескольких примерах. Каждый пример — отдельный эксперимент. Вы сами выбираете, сколько примеров взять и насколько глубоко копать.

**Минимум для зачёта:** 3 эксперимента + устная защита.

**Максимум:** вы можете взять любой свой код (старые лабы по Kotlin, свой pet-проект, что угодно) и разобрать его. Если результат будет содержательным — это зачтётся вместо любого задания из списка.

## Эксперименты

### Эксперимент 1. Базовое сложение

```kotlin
fun main() {
    val a = 5
    val b = 10
    val sum = a + b
    println(sum)
}
```

**Задача:**
1. Скомпилировать, запустить, убедиться, что выводит `15`.
2. Открыть байт-код.
3. Найти и выписать инструкции:
    - загрузки констант (`ICONST_5`, `BIPUSH 10` или другие);
    - сохранения в локальные переменные (`ISTORE`);
    - загрузки переменных (`ILOAD`);
    - сложения (`IADD`);
    - вызова `println`.

**Вопрос:** почему для `5` и `10` используются разные инструкции? Найдите ответ самостоятельно — это связано с тем, как JVM кодирует константы.

**Для отчёта:** заполните таблицу «инструкция → что на стеке после неё». Пример:

| Инструкция | Стек |
|------------|------|
| `ICONST_5` | `[5]` |
| `ISTORE 0` | `[]` |
| `BIPUSH 10` | `[10]` |
| ... | ... |

### Эксперимент 2. Типы данных и слоты

```kotlin
fun main() {
    val a: Long = 5
    val b: Long = 10
    println(a + b)

    val x: Double = 2.5
    val y: Double = 4.0
    println(x + y)
}
```

**Задача:**
1. Найти инструкции для `Long` (`LADD`, `LCONST`, `LDC2_W`).
2. Найти инструкции для `Double` (`DADD`, `DCONST`, `LDC2_W`).
3. Обратить внимание на **номера слотов** локальных переменных. `LSTORE 0`, потом `LSTORE 2` — почему не `1`?

**Вопрос:** почему `Long` и `Double` занимают по два слота, а `Int` — один?

**Дополнительно (по желанию):** проверьте `Short`, `Byte`, `Char`, `Boolean`. Сделайте таблицу «тип → количество слотов → характерные инструкции».

### Эксперимент 3. Ветвление

```kotlin
fun main() {
    val a = readln().toInt()
    val b = readln().toInt()
    val max = if (a > b) a else b
    println(max)
}
```

**Задача:**
1. Найти инструкцию сравнения (`IF_ICMPLE` или похожую).
2. Найти безусловный переход (`GOTO`).
3. Найти метки (`L1`, `L2`, ...).

**Вопрос:** нарисуйте схему переходов — куда прыгает выполнение в каждом случае.

**Дополнительно:** замените `if-else` на `when` с 3-4 ветками. Сколько условных переходов появилось? Есть ли разница в байт-коде между `if` и `when`?

### Эксперимент 4. Циклы

```kotlin
fun main() {
    var sum = 0
    for (i in 1..5) {
        sum += i
    }
    println(sum)
}
```

**Задача:**
1. Найти инициализацию счётчика.
2. Найти проверку условия.
3. Найти тело цикла (`IADD`).
4. Найти инкремент счётчика (`IINC`).
5. Найти обратный переход в начало тела (`GOTO`).

**Вопрос:** в чём разница между `for`, `while` и `do-while` на уровне байт-кода? Возьмите по одному примеру каждого и сравните.

**Дополнительно:** попробуйте `for (i in 1..5 step 2)`, `for (i in 5 downTo 1)`. Как меняется байт-код?

### Эксперимент 5. Функции и стек вызовов

```kotlin
fun add(x: Int, y: Int): Int {
    return x + y
}

fun main() {
    val result = add(3, 4)
    println(result)
}
```

**Задача:**
1. Найти `INVOKESTATIC`.
2. Найти `ILOAD 0`, `ILOAD 1` внутри `add`. Почему именно `0` и `1`, а не `x` и `y`?
3. Найти `IRETURN`.

**Вопрос:** где хранятся параметры функции? Где — результат? Что происходит с кадром стека при вызове?

**Дополнительно:** напишите рекурсивную функцию (например, факториал). Что происходит с кадром стека при каждом вызове? А что если сделать две взаимно рекурсивные функции?

### Эксперимент 6. Массивы

```kotlin
fun main() {
    val arr = intArrayOf(1, 2, 3)
    var sum = 0
    for (x in arr) {
        sum += x
    }
    println(sum)
}
```

**Задача:**
1. Найти `NEWARRAY` — создание массива.
2. Найти `IASTORE` — запись элемента.
3. Найти `IALOAD` — чтение элемента.
4. Найти `ARRAYLENGTH` — если используется.

**Вопрос:** как массив располагается в памяти? Почему это важно для производительности?

**Дополнительно (для тех, кто хочет копнуть глубже):** напишите обход матрицы 1000×1000 по строкам и по столбцам. Замерьте время через `System.nanoTime()`. Разница будет заметна — объясните, с чем она связана. Подсказка: кэш-линия процессора.
