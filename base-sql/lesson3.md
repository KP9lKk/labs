### Лабораторная работа №3: Наполнение базы данных и базовые SQL-запросы (`INSERT`, `SELECT`)

#### 1. Входные данные (Контекст)

Каждая пара использует рабочую схему `schema.sql`, созданную и проверенную в Лабораторной работе №2. Задача — написать SQL-скрипт заполнения базы тестовыми данными (`data.sql`) и сформировать набор аналитических запросов на чтение (`queries.sql`).

---

#### 2. Справка по командам и примеры использования

##### Команда `INSERT INTO` (Добавление данных)

Используется для добавления новых строк в таблицу. Для столбцов со свойством `INT GENERATED ALWAYS AS IDENTITY` значение **не передается** — СУБД генерирует его автоматически.

```sql
-- Пример 1: Заполнение справочника (одна строка)
INSERT INTO artist (artist_name) 
VALUES ('Mitsuhiro Arita');

-- Пример 2: Множественная вставка (несколько строк за раз)
INSERT INTO attack (attack_title, attack_damage) VALUES 
    ('Fire Spin', 100),
    ('Flamethrower', 90),
    ('Slash', 30);

-- Пример 3: Заполнение таблицы с внешним ключом
INSERT INTO card (card_name, card_hp, card_stage, artist_id) 
VALUES ('Charizard', 120, 'Stage 2', 1);

```

##### Команда `SELECT` (Чтение и фильтрация)

Используется для выборки данных из таблиц.

```sql
-- Пример 1: Выборка конкретных столбцов
SELECT card_name, card_hp 
FROM card;

-- Пример 2: Фильтрация по числовому условию и тексту
SELECT card_name, card_hp 
FROM card 
WHERE card_hp >= 100 AND card_stage = 'Stage 2';

-- Пример 3: Поиск по фрагменту текста (ILIKE — регистронезависимый поиск)
SELECT card_name 
FROM card 
WHERE card_name ILIKE '%zard%'; -- Найдет Charizard, Mega Charizard и т.д.

-- Пример 4: Сортировка по убыванию и ограничение количества строк
SELECT attack_title, attack_damage 
FROM attack 
ORDER BY attack_damage DESC 
LIMIT 2;

```

#### 3. Требования к файлу наполнения (`data.sql`)

Скрипт должен наполнять базу данными вашей карточки Покемона **плюс минимум 3 дополнительных карт** (чтобы в сумме в базе было не менее 4 карточек).

* **Соблюдение порядка вставки:**
1. Справочники художников (`artist`), типов энергии (`energy_type`) и атак (`attack`).
2. Таблица карточек (`card`).
3. Связующие таблицы (`card_attack`, `attack_energy`).


* **Корректность типов и `IDENTITY`:**
* Не передавать ручные значения в столбцы `*_id`, объявленные как `INT GENERATED ALWAYS AS IDENTITY`.
* Текстовые данные передавать в одиночных кавычках (`'Charizard'`).



---

#### 4. Требования к файлу запросов (`queries.sql`)

Студенты должны написать **6 отдельных SQL-запросов** чтения к своей базе данных:

1. **Запрос 1:** Вывести названия (`card_name`) и здоровье (`card_hp`) всех карточек, у которых здоровье строго больше 60.
2. **Запрос 2:** Вывести список всех атак (`attack_title` и `attack_damage`), сортированный по убыванию урона (`attack_damage`).
3. **Запрос 3:** Вывести 2 самых сильных атак по урону (использовать `LIMIT`).
4. **Запрос 4:** Найти карточку по частичному совпадению имени с использованием оператора `ILIKE` (например, все карты, содержащие фрагмент `'pi'`).
5. **Запрос 5:** Вывести список карточек, у которых стадия равна `'Basic'` ИЛИ здоровье больше 100 (использование `AND` / `OR`).
6. **Запрос 6:** Вывести типы энергии из таблицы `energy_type`, имя которых входит в заданный список с помощью оператора `IN ('Fire', 'Water', 'Lightning')`.
