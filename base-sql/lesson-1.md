
### Лабораторная работа №-1: Проектирование сущностей и типов данных базы данных «Pokémon TCG»

#### 1. Входные данные (Контекст)

Каждый студент (или пара студентов) получает изображение карточки Покемона (например, Пикачу). База данных должна быть спроектирована так, чтобы хранить не только параметры этой конкретной карты, но и быть готовой к загрузке тысяч других карт из различных выпусков.

Работа выполняется **в простом текстовом файле** (`.txt` или `.md`) без построения графических связей и без использования SQL-кода.

**Обязательные элементы карточки для анализа:**

* **Параметры покемона:** Имя, стадия (Stage), очки здоровья (HP), номер в Покедексе, вид/категория, рост (в метрах), вес (в кг), цена отступления (Retreat Cost), год выпуска.
* **Выпуск (Сет):** Код сета, название сета, общее количество карт в сете, дата выхода.
* **Боевые способности:** Название атаки, базовый урон, текстовый эффект.
* **Стихия:** Название типа элемента (Электричество, Огонь, Вода и т.д.).
* **Авторство:** Имя/псевдоним художника (иллюстратора).

---

#### 2. Требования к стандарту именования (Code Style)

Применяется индустриальный стандарт **Table-Prefixed Naming** в формате `snake_case`:

* **Сущности (Таблицы):** Имена сущностей строго в **единственном числе** на английском языке в нижнем регистре (`card`, `card_set`, `attack`, `element_type`, `illustrator`).
* **Атрибуты (Столбцы):** Каждое поле обязано содержать **префикс имени своей сущности** (`card_name`, `card_hp`, `set_name`, `attack_base_damage`, `illustrator_name`).
* **Лаконичность:** Избегать тавтологий вроде `card_card_name`. Префикс указывается ровно один раз.

---

#### 3. Требования к архитектуре (Что должно быть в файле)

* **Выделение сущностей:**
  Описать ровно **5 логических сущностей**:
  1. `card` — параметры самой карточки.
  2. `card_set` — информация о выпуске/сете.
  3. `attack` — свойства атаки/способности.
  4. `element_type` — справочник типов стихий.
  5. `illustrator` — данные о художнике.

* **Типы данных:**
  Для каждого поля необходимо выбрать один из 4 базовых типов:
  * `TEXT` — для текстовых строк, имен, описаний и комбинированного урона (например, `20+`).
  * `INT` — для целых чисел (HP, количества, года).
  * `NUMERIC` — для точных дробных чисел (рост, вес).
  * `DATE` — для календарных дат (`YYYY-MM-DD`).

---

#### 4. Образец оформления работы

В начале вашего текстового файла выведите демонстрационный пример, разобранный на занятии, а затем опишите оставшиеся сущности.

```

#### 5. Чек-лист самопроверки перед сдачей

* [ ] Все 5 сущностей названы на английском языке в единственном числе (`card`, а не `cards`)?
* [ ] Каждое поле содержит префикс своей таблицы (`card_hp`, `set_release_date`)?
* [ ] Поле урона атаки (`attack_base_damage`) имеет тип `TEXT` (учитывает значения `20+` и `30x`)?
* [ ] Поля роста (`card_height_m`) и веса (`card_weight_kg`) имеют тип `NUMERIC`, а не `INT`?
* [ ] Номер карты в сете (`card_number_in_set`) имеет тип `TEXT` (учитывает слэш `42/146`)?
