### Лабораторная работа №2: Реализация схемы «Pokémon TCG» в SQL DDL

#### 1. Входные данные (Контекст)

Каждая пара использует ER-диаграмму, спроектированную в Лабораторной работе №1. Задача — перевести схему в рабочий SQL DDL-скрипт (`schema.sql`) и проверить его выполнение на базе данных PostgreSQL.

---

#### 2. Требования к стандарту именования (Code Style) и типам данных PostgreSQL

* **Таблицы:** Имена сущностей строго в **единственном числе** (`card`, `artist`, `attack`, `energy_type`).
* **Столбцы:** Каждое поле должно содержать **префикс своей сущности** (`card_name`, `artist_name`, `attack_damage`, `energy_quantity`).
* **Автоинкремент (PK):** Для автоинкрементных первичных ключей использовать стандартный тип **`INT GENERATED ALWAYS AS IDENTITY`** (вместо устаревшего `SERIAL`).
* **Текстовые поля:** Для всех строковых атрибутов использовать тип **`TEXT`** (вместо `VARCHAR`).
* **Ключи:** Внешний ключ (`FOREIGN KEY`) должен полностью совпадать по имени с первичным ключом (`PRIMARY KEY`) родительской таблицы (например, `artist_id` в таблице `card`).

---

#### 3. Требования к архитектуре скрипта (`schema.sql`)

* **Создание таблиц:**
* Написать команды `CREATE TABLE` минимум для **5 таблиц** (`card`, `artist`, `attack`, `energy_type`, `card_attack`, `attack_energy`).
* Соблюсти правильный порядок создания: сначала справочники, затем основные сущности, в конце — связующие таблицы.


* **Ключи и Ограничения целостности:**
* Указать `PRIMARY KEY` с `INT GENERATED ALWAYS AS IDENTITY` для основных таблиц и составные первичные ключи для связующих.
* Настроить `FOREIGN KEY` для связи таблиц без указания каскадных правил.
* Добавить ограничение `NOT NULL` для всех обязательных полей.
* Добавить ограничения `CHECK` для числовых параметров (`card_hp > 0`, `attack_damage >= 0`, `energy_quantity > 0`).



---

#### 4. Пример идеального синтаксиса таблицы на лекции (для демонстрации)

```sql
CREATE TABLE artist (
    artist_id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    artist_name TEXT NOT NULL
);

CREATE TABLE card (
    card_id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    card_name TEXT NOT NULL,
    card_hp INT NOT NULL CHECK (card_hp > 0),
    artist_id INT REFERENCES artist(artist_id)
);

```
