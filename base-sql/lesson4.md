#### 2. Справка по типам соединений и синтаксису

##### Общий обзор типов JOIN

* **`INNER JOIN` (Внутреннее соединение):** Возвращает только те строки, для которых найдено точное совпадение ключей в обеих таблицах.
* **`LEFT JOIN` (Левое внешнее соединение):** Возвращает **все строки** из левой таблицы. Если в правой таблице совпадений нет, подставляется значение `NULL`.
* **`RIGHT JOIN` / `FULL OUTER JOIN`:** В реальной разработке `RIGHT JOIN` избегают для сохранения читаемости кода (его заменяют на `LEFT JOIN`, изменив порядок таблиц). `FULL OUTER JOIN` используется крайне редко для полного объединения несвязанных наборов.

##### Синтаксис ON vs USING

Благодаря нашему стандарту именования (где первичный ключ `artist_id` называется точно так же, как и внешний ключ `artist_id`), мы используем лаконичный синтаксис `USING (...)`:

```sql
-- 1. INNER JOIN с использованием USING:
SELECT card_name, artist_name 
FROM card 
JOIN artist USING (artist_id);

-- 2. LEFT JOIN (сохраняет все карты, даже если artist_id IS NULL):
SELECT card_name, artist_name 
FROM card 
LEFT JOIN artist USING (artist_id);

-- 3. Соединение M:N через промежуточную таблицу (3 таблицы):
SELECT card_name, attack_title, attack_damage 
FROM card 
JOIN card_attack USING (card_id) 
JOIN attack USING (attack_id);

```
