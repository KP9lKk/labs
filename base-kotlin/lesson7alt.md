# Лабораторная работа № 7

## Тема: Nullable-типы в Kotlin. Безопасная работа с `null` и обработка отсутствующих значений в Pokémon TCG

**Цель работы:** Освоить nullable-типы (`Type?`), безопасный вызов (`?.`), оператор Элвиса (`?:`), проверки на `null` через `if` и `?.let`, а также осознанное применение `!!`. Научиться обрабатывать консольный ввод и элементы коллекций так, чтобы программа не завершалась аварийно с `NullPointerException` при любых входных данных.

---

### 1. Краткие теоретические сведения

В Kotlin система типов строго разделяет значения, которые **могут** быть `null`, и значения, которые **не могут**. Обычный тип (`String`, `Int`, `List<String>`) не допускает `null`: попытка присвоить `null` такой переменной приводит к ошибке компиляции. Если значение может отсутствовать, тип помечается знаком `?`.

#### **A. Объявление nullable-переменной**

```kotlin
val card: String = "Pikachu"      // никогда не null
val maybeCard: String? = null     // может быть null — обратите внимание на "?"
// val broken: String = null       // ошибка компиляции
```

Такая защита выявляет ошибки ещё на этапе сборки, а не во время выполнения. В языках без подобной проверки (например, в Java) обращение к `null` приводит к аварийному завершению программы с `NullPointerException`.

#### **B. Инструменты работы с nullable-значениями**

| Инструмент | Назначение | Поведение при `null` |
|---|---|---|
| `?.` | безопасный вызов метода или свойства | возвращает `null` |
| `?:` | значение по умолчанию | возвращает правый операнд |
| `if (x != null)` | проверка перед использованием | блок не выполняется |
| `x?.let { }` | блок только для non-null значения | блок не выполняется |
| `!!` | принудительное разыменование | выбрасывает `NullPointerException` |
| `?: return` | ранний выход из функции | прерывает выполнение |

```kotlin
val name: String? = null
println(name?.length)              // null
println(name ?: "Безымянный")      // Безымянный
println(name?.uppercase() ?: "-")  // -
```

#### **C. Безопасные аналоги стандартных функций**

Многие функции стандартной библиотеки, изученные в предыдущих работах, имеют «безопасные» варианты, возвращающие `null` вместо исключения:

| Обычный вызов | Безопасный вариант | Возвращает |
|---|---|---|
| `readln()` | `readlnOrNull()` | `String?` |
| `"5".toInt()` | `"5".toIntOrNull()` | `Int?` |
| `list[10]` | `list.getOrNull(10)` | `T?` |
| `list.last()` | `list.lastOrNull()` | `T?` |
| `list.first { ... }` | `list.firstOrNull { ... }` | `T?` |

Доступ к элементу `Map` по ключу (`map["key"]`) изначально возвращает nullable-значение `V?`, поскольку ключа может не быть в словаре.

#### **D. Smart cast**

Компилятор Kotlin способен самостоятельно отслеживать, в какой ветке кода переменная гарантированно не равна `null`. Внутри блока `if (x != null)` разрешено обращаться к `x` как к обычному (non-null) значению — без `?.` и `!!`:

```kotlin
val input: String? = "Potion"
if (input != null) {
    println(input.length)      // ошибки нет: компилятор знает, что input не null
}
```

Smart cast работает для неизменяемых (`val`) переменных. Для изменяемых (`var`) он применяется только в том случае, если после проверки переменная не переприсваивалась.

#### **Часть 4. Безопасные коллекции и итоговый сценарий**

**Формулировка задачи:** Применить безопасные аналоги стандартных функций коллекций, а затем построить программу, устойчивую к любому консольному вводу.

##### Техническое задание:

1. Создайте коллекцию и выполните серию безопасных вызовов:

```kotlin
val hand: MutableList<String> = mutableListOf("Pikachu", "Potion")
println(hand.getOrNull(10))                     // null
println(hand.firstOrNull { it.length > 10 })    // null
println(hand.lastOrNull())                      // Potion
println(hand.randomOrNull())                    // случайный элемент
```

2. Опустошите коллекцию методом `clear()` и повторите два последних вызова. Убедитесь, что программа **не завершается аварийно**.
3. Реализуйте цикл обхода коллекции без явного счётчика, используя nullable-возврат метода `removeLastOrNull()`:

```kotlin
val deck: MutableList<String> = mutableListOf("A", "B", "C")
while (deck.removeLastOrNull() != null) {
    // тело пустое — цикл идёт, пока в колоде есть элементы
}
println("Колода пуста: ${deck.isEmpty()}")
```

4. Реализуйте **итоговую программу** — «Безопасный калькулятор хода». Программа последовательно запрашивает три параметра, каждый из которых пользователь может пропустить, нажав Enter:

```kotlin

println("Введите урон (Enter — по умолчанию 0):")

5. Обработайте каждое значение через `?:` с использованием соответствующих безопасных преобразований:

val damage: Int = damageRaw?.trim()?.toIntOrNull() ?: 0

```

6. Вычислите итоговый урон и выведите отчёт:

```kotlin

```

7. Проверьте работу программы на следующих наборах входных данных:

| Значение 1 | Значение 2 | Значение 3 | Ожидаемый результат |
