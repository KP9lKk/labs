# Лабораторная работа № 7

## Тема: Nullable-типы в Kotlin. Безопасная работа с `null` и обработка отсутствующих значений

**Цель работы:** Освоить nullable-типы (`Type?`), безопасный вызов (`?.`), оператор Элвиса (`?:`), проверки `if (x != null)` и `?.let`, понять назначение и опасность `!!`. Научиться обрабатывать консольный ввод и элементы коллекций так, чтобы программа **не падала с `NullPointerException`** ни на каком вводе.

---

### 1. Краткие теоретические сведения

#### **A. Зачем нужен nullable-тип**

В Kotlin тип без `?` **не может** содержать `null` — компилятор это запрещает. Если значение может отсутствовать, тип помечается знаком `?`:

```kotlin
val name: String = "Pikachu"    // всегда есть значение
val nickname: String? = null    // может быть null — обратите внимание на "?"
// val broken: String = null    // ← ошибка компиляции
```

Такая защита ловит миллионы багов ещё **до** запуска программы. В Java, например, такой защиты нет, и это одна из самых частых причин падений в продакшене.

#### **B. Шесть инструментов работы с null**

| Инструмент | Что делает | Если `null` |
|---|---|---|
| `?.` | безопасный вызов метода | вернёт `null` |
| `?:` | значение по умолчанию | вернёт правое |
| `if (x != null)` | проверка | пропустит блок |
| `x?.let { }` | блок только для non-null | ничего не выполнит |
| `!!` | «клянусь, что не null» | 💥 `NullPointerException` |
| `?: return` | ранний выход | прервёт выполнение |

#### **C. Связь с уже пройденным**

Всё, что вы изучали в лабах 1–5, имеет «безопасный» nullable-вариант:

| Обычный вызов | Безопасный вариант | Что возвращает |
|---|---|---|
| `readln()` | `readlnOrNull()` | `String?` — null при прерывании |
| `"5".toInt()` | `"5".toIntOrNull()` | `Int?` — null при плохом вводе |
| `list[10]` | `list.getOrNull(10)` | `T?` — null вместо исключения |
| `list.last()` | `list.lastOrNull()` | `T?` — null если список пуст |
| `map["key"]` | `map["key"]` | уже возвращает `V?` |

Эти функции — не «ещё одна тема». Это следующий логический шаг после всего, что вы уже умеете.

#### **Задание 4. `if` vs `?.let` — два стиля**

**Цель:** сравнить классический подход с функциональным.

1. Создайте переменную:

```kotlin
val energy: String? = "Fire Energy"
```

2. Напишите две версии одного действия — вывести длину строки, если она есть.

**Версия A (классическая):**

```kotlin
if (energy != null) {
    println("A: длина = ${energy.length}")
} else {
    println("A: энергии нет")
}
```

**Версия B (через `let`):**

```kotlin
energy?.let {
    println("B: длина = ${it.length}")
} ?: println("B: энергии нет")
```

> Обратите внимание: внутри `let` переменная `it` — уже **гарантированно не null**, поэтому `it.length` пишется без `?.` и без `!!`.

3. Проверьте оба варианта при `energy = "Fire Energy"` и при `energy = null`.

**Контрольная точка:** обе версии дают одинаковый результат. Разница только в стиле.

**Результат:** у вас в руках **два инструмента** для одной задачи. В реальном коде вы будете выбирать по ситуации — это и есть профессиональный подход.

#### **Задание 5. Smart cast — компилятор думает за вас**

**Цель:** увидеть, что компилятор Kotlin следит за потоком выполнения.

1. Напишите:

```kotlin
val input: String? = "Potion"
if (input != null) {
    println(input.length)       // ← здесь нет ни ?., ни !!
    println(input.uppercase())  // ← и здесь тоже
}
```

2. Запустите — всё компилируется и работает. Компилятор **сам понял**, что внутри `if` переменная не может быть null. Это называется **smart cast**.
3. Теперь попробуйте сломать smart cast:

```kotlin
var mutableInput: String? = "Potion"
if (mutableInput != null) {
    mutableInput = null
    // println(mutableInput.length)   // ← раскомментируйте эту строку
}
```

4. Раскомментируйте последнюю строку и посмотрите, что скажет компилятор.

**Контрольный вопрос:** почему для `val` smart cast работает, а для `var` — не всегда?

**Результат:** вы видели «aha»-момент Kotlin. Компилятор не просто запрещает — он **анализирует** ваш код.

#### **Задание 6. Безопасные коллекции**

**Цель:** заменить опасные методы коллекций на безопасные аналоги.

1. Создайте:

```kotlin
val hand: MutableList<String> = mutableListOf("Pikachu", "Potion")
```

2. Для каждого выражения **предскажите результат**, потом проверьте через `println()`:

```kotlin
println(hand.getOrNull(10))                     // ?
println(hand.firstOrNull { it.length > 10 })    // ?
println(hand.lastOrNull())                      // ?
println(hand.randomOrNull())                    // ?
```

3. Теперь **опустошите** список и повторите:

```kotlin
hand.clear()
println(hand.lastOrNull())                      // ?
println(hand.randomOrNull())                    // ?
```

4. А теперь классический трюк — цикл `while` через null:

```kotlin
val deck: MutableList<String> = mutableListOf("A", "B", "C")
while (deck.removeLastOrNull() != null) {
    // тело пустое — цикл идёт, пока в колоде есть карты
}
println("Колода пуста: ${deck.isEmpty()}")
```

**Контрольная точка:** все вызовы вернули `null`, а не уронили программу. Цикл `while` корректно завершился **без явного счётчика**.

**Результат:** вы умеете безопасно работать с пустыми коллекциями. Это то, что отличает падающий код от продакшн-кода.

#### **Задание 7. Реальный сценарий — безопасный ввод**

**Цель:** собрать все инструменты вместе на реалистичной задаче.

1. Напишите программу, которая запрашивает количество энергии и корректно обрабатывает **любой** ввод:

```kotlin

val raw: String? = readlnOrNull()
val energy: Int = raw?.trim()?.toIntOrNull() ?: 0

if (energy <= 0) {
    println("Прикреплено 0 энергии (ввод некорректен или пуст)")

    println("Прикреплено $energy энергии")
}
```

2. **Проверьте программу на всех сценариях:**

| Что вводим | Что должна вывести программа |
|---|---|
| `5` | `Прикреплено 5 энергии` |
| *(пустая строка, просто Enter)* | `Прикреплено 0 энергии (ввод некорректен или пуст)` |

**Контрольная точка:** программа **не упала ни разу**. Ни на пустой строке, ни на буквах, ни на отрицательном числе.

**Результат:** это **настоящий паттерн из продакшн-кода**. Именно так обрабатывают пользовательский ввод в реальных приложениях. Вы только что написали код уровня junior+ и не использовали ни одного `!!`.

#### **Задание 8. Итоговая задача — безопасный калькулятор хода**

**Цель:** применить все инструменты в одной программе.

**Сценарий:** игрок вводит данные для боевого хода. Любое поле может быть не заполнено — программа должна использовать разумные значения по умолчанию и **не падать**.

3. Посчитайте итоговый урон:

```kotlin
val finalDamage: Double = damage * bonus
```

4. Выведите отчёт по шаблону:

**Финальная проверка — 5 запусков:**

**Результат:** вы написали программу, которая **устойчива к любому пользовательскому вводу**. Именно так выглядит код, который не стыдно показать на собеседовании.
