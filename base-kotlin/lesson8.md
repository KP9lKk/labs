### 1. Краткие теоретические сведения

#### **A. Зачем нужны классы**

В лабах 1–7 данные жили в отдельных переменных и коллекциях: `name1`, `hp1`, `hp2`… Как только сущностей становится больше одной, такой код превращается в кашу — забыли обновить одно поле, перепутали индекс. Класс — это **шаблон**, который объединяет **данные (свойства)** и **поведение (методы)** в одну сущность.

**Пример без класса (так было в лабах 1–7):**

```kotlin
// Данные «размазаны» по переменным — легко перепутать
val name1 = "Pikachu";  var hp1 = 100
val name2 = "Charmander"; var hp2 = 80

hp1 -= 20                        // урон по первому
println("$name1: $hp1, $name2: $hp2")
// А теперь попробуйте написать heal для обоих — и не запутаться
```

**Пример с классом — данные и поведение вместе:**

```kotlin
class Pokemon(val name: String, var hp: Int) {
    fun isAlive(): Boolean = hp > 0
    fun takeDamage(amount: Int) { hp = (hp - amount).coerceAtLeast(0) }
}

val pikachu = Pokemon("Pikachu", 100)     // создание экземпляра
val charmander = Pokemon("Charmander", 80)

pikachu.takeDamage(20)                     // «урон» — это метод объекта
println("${pikachu.name}: ${pikachu.hp}")  // Pikachu: 80
println("${charmander.name}: ${charmander.hp}") // Charmander: 80

// Код читается как предложение: «пикачу получает урон 20»
```

Разница очевидна: с классом невозможно «перепутать» HP Пикачу и HP Чармандера — каждый объект хранит свои данные.

#### **B. Первичный конструктор: `val` vs `var`**

Свойства можно объявить **прямо в скобках конструктора**. `val` = только чтение, `var` = изменяемое.

```kotlin
class Pokemon(
    val name: String,     // имя не меняется — val
    var hp: Int,          // HP меняется в бою — var
    val maxHp: Int        // максимум не меняется — val
)

val p = Pokemon("Pikachu", 100, 100)

p.hp = 80                 // ✅ var — можно
println(p.hp)             // 80

// p.name = "Raichu"      // ❌ val — ошибка компиляции: "Val cannot be reassigned"
// p.maxHp = 120          // ❌ val — ошибка компиляции
```

> **Важно:** `val` запрещает **переприсвоение ссылки**, но не запрещает менять **объект по ссылке**. Пример:

```kotlin
val team = mutableListOf<Pokemon>()   // val — ссылку не переприсвоить
team.add(Pokemon("Pikachu", 100, 100)) // ✅ объект по ссылке менять можно
team.add(Pokemon("Eevee", 50, 50))
println(team.size)                     // 2

// team = mutableListOf()              // ❌ нельзя — val
```

#### **C. `init`-блок и `require` — защита инварианта**

`init { }` выполняется **при создании** объекта, до того как он вернётся вызывающему коду. `require(условие) { "сообщение" }` бросает `IllegalArgumentException`, если условие ложно.

**Пример: защищаем покемона от «невозможного» состояния**

```kotlin
class Pokemon(val name: String, var hp: Int, val maxHp: Int) {

    init {
        require(name.isNotBlank()) { "Имя не может быть пустым" }
        require(maxHp in 1..999)  { "maxHp должен быть в 1..999, получено $maxHp" }
        require(hp in 0..maxHp)   { "hp должен быть в 0..maxHp, получено $hp" }
    }
}

val ok = Pokemon("Pikachu", 100, 100)     // ✅ ок
// val bad1 = Pokemon("", 100, 100)       // 💥 IllegalArgumentException: Имя не может быть пустым
// val bad2 = Pokemon("Mewtwo", 5000, 100) // 💥 IllegalArgumentException: hp должен быть в 0..maxHp
```

**Что это даёт:** объект с «плохими» данными **не существует**. Программа падает сразу и в понятном месте, а не через час в бою, где `hp = -50` ломает всю логику.

#### **D. Методы, меняющие состояние**

Метод — это функция **внутри класса**, у которой есть доступ к свойствам через `this`. Методы могут **возвращать полезный результат** — не только менять состояние.

**Пример: `takeDamage` возвращает, сколько HP реально снято**

```kotlin
class Pokemon(val name: String, var hp: Int, val maxHp: Int) {

    init {
        require(name.isNotBlank()) { "Имя не может быть пустым" }
        require(maxHp in 1..999)   { "maxHp должен быть в 1..999" }
        require(hp in 0..maxHp)    { "hp должен быть в 0..maxHp" }
    }

    fun isAlive(): Boolean = hp > 0

    fun takeDamage(amount: Int): Int {
        require(amount >= 0) { "Урон не может быть отрицательным" }
        val before = hp
        hp = (hp - amount).coerceAtLeast(0)
        return before - hp            // сколько HP реально снято
    }

    fun heal(amount: Int): Int {
        require(amount >= 0) { "Лечение не может быть отрицательным" }
        val before = hp
        hp = (hp + amount).coerceAtMost(maxHp)
        return hp - before            // сколько HP реально восстановлено
    }
}

val p = Pokemon("Bulbasaur", hp = 30, maxHp = 100)
println(p.takeDamage(50))   // 30 — реально снято только 30, хотя «урон» был 50
println(p.hp)               // 0
println(p.heal(200))        // 100 — реально восстановлено только 100 (до maxHp)
println(p.hp)               // 100
println(p.heal(50))         // 0 — уже полный HP, лечить нечего
```

**Зачем возвращать `Int`, а не `Unit`:** вызывающий код может напечатать «Charmander получил 20 урона, но у него было только 10, реально снято 10» — это возможно только если метод вернул «реально снято».

#### **E. Параметры со значениями по умолчанию**

Значения по умолчанию позволяют **не указывать** параметр при создании — подставится значение из объявления.

```kotlin
class Pokemon(
    val name: String,
    var hp: Int = 100,          // по умолчанию 100
    val maxHp: Int = 100,       // по умолчанию 100
    val level: Int = 1          // по умолчанию 1
) {
    init {
        require(name.isNotBlank()) { "Имя не может быть пустым" }
        require(maxHp in 1..999)   { "maxHp должен быть в 1..999" }
        require(hp in 0..maxHp)    { "hp должен быть в 0..maxHp" }
        require(level in 1..100)   { "level должен быть в 1..100" }
    }
}

val a = Pokemon("Pikachu")                          // hp=100, maxHp=100, level=1
val b = Pokemon("Machamp", hp = 80, maxHp = 120)    // level=1 (по умолчанию)
val c = Pokemon("Mewtwo", level = 70)               // hp=100, maxHp=100, level=70

println("${a.name}: ${a.hp}/${a.maxHp}, lvl ${a.level}")   // Pikachu: 100/100, lvl 1
println("${b.name}: ${b.hp}/${b.maxHp}, lvl ${b.level}")   // Machamp: 80/120, lvl 1
println("${c.name}: ${c.hp}/${c.maxHp}, lvl ${c.level}")   // Mewtwo: 100/100, lvl 70
```

> **Именованные аргументы** (`hp = 80`) позволяют пропустить параметры в середине и указать только нужные. Без них пришлось бы писать `Pokemon("Machamp", 80, 120, 1)` — и легко перепутать `hp` с `maxHp`.

#### **F. `data class` — что генерируется автоматически**

`data class` генерирует 4 метода: `equals`, `hashCode`, `toString`, `copy`. Обычный `class` их **не** генерирует — он наследует от `Any`, где `equals` сравнивает **ссылки**, а `toString` печатает адрес.

**Пример: обычный класс vs `data class`**

```kotlin
class NormalCard(val name: String, val level: Int)

data class DataCard(val name: String, val level: Int)

val n1 = NormalCard("Pikachu", 25)
val n2 = NormalCard("Pikachu", 25)
println(n1)                 // NormalCard@1b6d3586  ← адрес, бесполезно
println(n1 == n2)           // false ← сравниваются ссылки, не значения

val d1 = DataCard("Pikachu", 25)
val d2 = DataCard("Pikachu", 25)
println(d1)                 // DataCard(name=Pikachu, level=25) ← красиво
println(d1 == d2)           // true ← сравниваются значения
println(d1.hashCode() == d2.hashCode())  // true ← согласован с equals

val d3 = d1.copy(level = 30)   // копия с изменением одного поля
println(d3)                    // DataCard(name=Pikachu, level=30)
println(d1)                    // DataCard(name=Pikachu, level=25) — оригинал не изменился
```

**Где это нужно на практике:**
- `equals` — сравнить две карты в руке: «это одна и та же карта?»;
- `hashCode` — положить карты в `Set` или использовать как ключ `Map`;
- `toString` — быстро напечатать объект в лог/отчёт;
- `copy` — сделать изменённую копию, не мутируя оригинал: `card.copy(level = card.level + 1)`.

#### **G. `companion object` — «статики» класса**

`companion object` — это объект-синглтон **внутри класса**. К его членам обращаются через имя класса: `Pokemon.MAX_LEVEL`. В нём обычно держат **константы** и **фабрики** — методы, создающие экземпляры.

```kotlin
class Pokemon(val name: String, var hp: Int = 100, val maxHp: Int = 100) {

    init {
        require(name.isNotBlank()) { "Имя не может быть пустым" }
        require(maxHp in 1..999)   { "maxHp должен быть в 1..999" }
        require(hp in 0..maxHp)    { "hp должен быть в 0..maxHp" }
    }

    companion object {
        const val MAX_LEVEL = 100

        // Фабрика: «дикий» покемон — маленький и слабый
        fun wild(name: String): Pokemon =
            Pokemon(name, hp = 30, maxHp = 30)

        // Фабрика: «элитный» покемон — сильный и живучий
        fun elite(name: String): Pokemon =
            Pokemon(name, hp = 200, maxHp = 200)
    }
}

val a = Pokemon("Pikachu")             // обычный: hp=100, maxHp=100
val b = Pokemon.wild("Pidgey")         // дикий: hp=30, maxHp=30
val c = Pokemon.elite("Mewtwo")        // элитный: hp=200, maxHp=200

println(Pokemon.MAX_LEVEL)             // 100
println("${b.name}: ${b.hp}/${b.maxHp}")   // Pidgey: 30/30
println("${c.name}: ${c.hp}/${c.maxHp}")   // Mewtwo: 200/200
```

**Зачем `companion object`, если есть `const val` верхнего уровня:**
- `Pokemon.MAX_LEVEL` — понятно, к чему относится константа;
- фабрика `Pokemon.wild(...)` «принадлежит» классу, а не висит в глобальном пространстве;
- автодополнение в IDE показывает члены `companion object` вместе с классом.

#### **H. Списки объектов — те же функции из лабы 6**

Список объектов обрабатывается **точно так же**, как список чисел: `filter`, `map`, `count`, `sumOf`, `maxByOrNull`. Меняется только тип `it` в лямбде — теперь это **объект**, а не `Int`.

```kotlin
class Pokemon(val name: String, var hp: Int, val maxHp: Int) {
    val isAlive: Boolean get() = hp > 0
}

val team: List<Pokemon> = listOf(
    Pokemon("Pikachu",    80, 100),
    Pokemon("Charmander", 40,  90),
    Pokemon("Squirtle",  100, 100),
    Pokemon("Caterpie",    0,  50)
)

println(team.size)                                       // 4
println(team.count { it.isAlive })                       // 3
println(team.sumOf { it.hp })                            // 220
println(team.maxByOrNull { it.hp }?.name)                // Squirtle
println(team.filter { it.isAlive }.map { it.name })      // [Pikachu, Charmander, Squirtle]
println(team.firstOrNull { !it.isAlive }?.name)          // Caterpie

// «Ударить» всех живых на 20
team.filter { it.isAlive }.forEach { it.takeDamage(20) }
team.forEach { println("${it.name}: ${it.hp}/${it.maxHp}") }
```

**Пустой список — безопасные результаты:**

```kotlin
val empty = listOf<Pokemon>()

println(empty.size)                              // 0
println(empty.sumOf { it.hp })                   // 0 — sumOf безопасен
println(empty.count { it.isAlive })              // 0
println(empty.maxByOrNull { it.hp }?.name ?: "нет покемонов")  // "нет покемонов"
println(empty.map { it.hp }.average().takeIf { !it.isNaN() } ?: 0.0) // 0.0
```

> Обратите внимание: `sumOf` и `count` на пустом списке возвращают `0` — это безопасно. `maxByOrNull` возвращает `null` — его нужно обработать через `?.` и `?:`. `average()` на пустом списке возвращает `NaN` — обрабатывайте отдельно.

#### **Задание 4. Методы, которые меняют состояние — проектируете API сами**

**Цель:** научиться писать методы, которые корректно обновляют свойства и **возвращают полезный результат**.

**Требования к классу:**
