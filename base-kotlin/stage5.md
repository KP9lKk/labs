## Техническое задание: Сквозной проект (Спринты 1–5)
## Разработка комплексного консольного движка Pokémon TCG
------------------------------
## 1. Контекст и архитектурная цель
Сквозной проект представляет собой поэтапную сборку базового движка для моделирования игровой сессии Pokémon TCG. На текущем этапе проект объединяет пять последовательных этапов разработки (Спринтов):

1. Спринт № 1: Оцифровка структуры данных карты Тренера.
2. Спринт № 2: Моделирование состояния игрового стола, работа с динамическими счетчиками ресурсов и кастинг типов.
3. Спринт № 3: Реализация движка правил, условных проверок (if-else, when) и вычисление базового статуса боя.
4. Спринт № 4: Интеграция циклических конструкций (while, do-while, for) для пошагового поиска карт, симуляции бросков монетки и проведения серийных атак.
5. Спринт № 5: Управление коллекциями карт (List, MutableList, Set, Map) и функциональный анализ игрового стола (filter, map, sortedBy, count, sumOf, joinToString).

Итоговая программа представляет собой единый исполняемый пайплайн (Main.kt), выполняющий обработку пользовательского ввода, фазу поиска и серийной атаки, а также полноценный функциональный аудит руки, колоды, сброса и пула ресурсов с использованием выразительных коллекционных операций Kotlin.
------------------------------
## 2. Спецификация данных

## 2.1. Входные текстовые параметры (Считываются через readln())

* Свойства карты (Спринт № 1): cardTypeInput, cardSubtypeInput, cardNameInput, effectTextInput, ruleTextInput, illustratorInput.
* Параметры состояния и боя (Спринты № 2–3):
    * deckSizeInput (String) — начальный размер колоды.
    * energyOnBoardInput (String) — доступный запас энергии на столе.
    * discardEnergyCostInput (String) — стоимость сброса энергии для атаки.
    * baseDamageInput (String) — базовый урон атаки.
    * attackerElementInput (String) — стихия атакующего Покемона ("Fire", "Water", "Grass").
    * defenderElementInput (String) — стихия защищающегося Покемона ("Fire", "Water", "Grass").
    * defenderHpInput (String) — текущее HP противника до атаки.
* Параметры управления циклами (Спринт № 4):
    * searchDepthInput (String) — глубина просмотра колоды пользователем для поиска карты стадиона.
    * coinResultInput (String) — ввод стороны монетки пользователем ("Heads" / "Tails").
    * attackStrikesInput (String) — количество ударов для серийной атаки.
* Входные данные коллекций и реестра (Спринт № 5):
    * initialHandInput (String) — список карт, приходящих в руку при стартовой раздаче (через запятую).
    * filterTypeInput (String) — тип карт для фильтрации в фазе анализа ("Pokemon", "Energy", "Trainer").
    * benchPokemonPowersInput (String) — урон атак Покемонов на скамейке запасных (через запятую, например: "30, 50, 20").

## 2.2. Коллекционные структуры данных (Спринт № 5)

* cardRegistry (Map<String, String>, val) — статический справочник типа «Название карты -> Тип карты» ("Pokemon", "Energy", "Trainer").
* cardDamageRegistry (Map<String, Int>, val) — справочник базового урона Покемонов («Название -> Урон»).
* fullDeck (MutableList<String>, val) — динамическая колода игрока (поддерживает методы `add` / `removeAt`).
* playerHand (MutableList<String>, val) — текущая рука игрока (изменяемый список).
* discardPile (MutableSet<String>, val) — кладбище/сброс карт (множество для гарантии учета уникальных сброшенных наименований).
* activePrizeSet (Set<String>, val) — фиксированное множество призовых карт текущего матча.

## 2.3. Вычисляемые показатели и функциональные метрики (Спринт № 5)

* filteredHandCards (List<String>, val) — результат работы `filter` по выбранному пользователем типу `filterTypeInput`.
* formattedHand (List<String>, val) — результат работы `map`, преобразующий названия карт в формат `[КАРТА]`.
* sortedHand (List<String>, val) — результат работы `sortedBy`, отсортировавший руку по алфавиту.
* matchingTypeCount (Int, val) — результат работы `count`, посчитавший карты заданного типа в руке.
* totalHandNameLength (Int, val) — результат работы `sumOf { it.length }`, оценивающий суммарную длину названий карт.
* benchTotalPower (Int, val) — результат работы `sumOf`, рассчитавший суммарный урон скамейки запасных.
* handViewString (String, val) — результат работы `joinToString` для красивого вывода руки.

## 3. Требования к алгоритму и логике работы
Программа Main.kt должна выполнять следующую цепочку действий:

## Блок 1–5 (Интеграция прошлых спринтов № 1–4)

1. Выполнить оцифровку карты Тренера (Спринт № 1).
2. Выполнить поиск карты Стадиона в цикле `while` с `break` и симуляцию бросков монетки в `do-while` до первого "Tails" (Спринт № 4).
3. Валидировать энергию и провести расчет урона с учетом стихийного коэффициента `when` (Спринты № 2–3).
4. Провести серийную атаку в цикле `for` с обработкой промахов через `continue` и нокаута через `break` (Спринт № 4).

## Блок 6. Инициализация и формирование коллекций (Спринт № 5)

1. **Реестр карт (Map):** Инициализировать `cardRegistry` парой десятков ключевых карт ("Pikachu" to "Pokemon", "Ultra Ball" to "Trainer", "Fire Energy" to "Energy" и т.д.) и `cardDamageRegistry` с уроном Покемонов.
2. **Инициализация колоды и руки (MutableList):**
    * Создать `fullDeck` из элементов колоды.
    * Запросить у пользователя с консоли `initialHandInput` (строка с названиями карт через запятую).
    * Разобрать строку через `.split(",")`, затримить пробелы и поместить карты в `playerHand`.
    * Синхронно удалить полученные карты из `fullDeck`.
3. **Формирование сброса (Set):** Сформировать `discardPile` (`MutableSet<String>`), поместив туда сброшенные карты энергии после атаки из Спринта № 2 и карты, использованные в фазе боя.

## Блок 7. Функциональный анализ и трансформации (Спринт № 5)

1. **Фильтрация по типу (`filter`):**
    * Запросить у пользователя тип карты для поиска: `print("Введите тип карт для аналитической выборки (Pokemon/Energy/Trainer): ")`.
    * С помощью `filter` отбрать из `playerHand` карты, чей тип в `cardRegistry` совпадает с введенным `filterTypeInput`.
2. **Трансформация названий (`map`):**
    * С помощью `map` преобразовать элементы `playerHand` в капс-формат вида `[NAME]`.
3. **Сортировка (`sortedBy`):**
    * Отсортировать текущий состав руки по алфавиту с помощью `sortedBy { it }`.
4. **Форматированный вывод (`joinToString`):**
    * Сформировать итоговые текстовые представления руки, отфильтрованных карт и сброса с кастомными разделителями (`", "`, `" | "`).

## Блок 8. Агрегация данных и расчет потенциала стола (`count`, `sumOf`, `Set`)

1. **Подсчет по условию (`count`):**
    * С помощью `count` посчитать точное количество карт выбранного типа в руке.
2. **Агрегация урона и характеристик (`sumOf`):**
    * Запросить у пользователя строки урона Покемонов на скамейке `benchPokemonPowersInput`.
    * Разобрать строку в список чисел и с помощью `sumOf { it }` вычислить суммарную боевую мощь скамейки запасных.
    * Вычислить суммарный объем символов в названиях карт руки через `playerHand.sumOf { it.length }`.
3. **Анализ уникальности и пересечений (Set Operations):**
    * Сформировать `activePrizeSet` (`setOf(...)`).
    * Вычислить пересечение карт в сбросе `discardPile` и призовом фонде через операции множеств или `filter { it in activePrizeSet }`.

## 5. Критерии оценки (3-балльная шкала)

## Оценка «5» (Отлично)

* Все 5 модулей сквозного проекта гармонично объединены в файле `Main.kt`.
* Для работы с динамическим состоянием руки и колоды применены `MutableList`, а для сброса — `MutableSet`.
* Справочник карт и их типов реализован через `Map<String, String>`.
* Операции `filter`, `map`, `sortedBy` корректно применены к коллекциям руки и возвращают новые коллекции без создания ручных циклов.
* Подсчеты выполнены с применением `count` и `sumOf`.
* Вывод коллекционных данных оформлен с использованием `joinToString` с явным указанием разделителей.

## Оценка «4» (Хорошо)

* Программа компилируется и правильно выполняет все этапы.
* Есть небольшие недочеты: например, вместо `sumOf` или `count` использован ручной цикл `for` поверх коллекции, или операция `map` заменена добавлением элементов в новый список внутри итератора.

## Оценка «3» (Удовлетворительно)

* Программа запускается, но функциональные операции над коллекциями практически не используются (все сделано через обычные массивы и циклы `for`).
* Возникают ошибки кастинга или `IndexOutOfBoundsException` при манипуляциях со списками карт.

## Оценка «2» / Не зачтено

* Код не компилируется, или студент не понимает разницу между изменяемыми (`MutableList`) и неизменяемыми (`List`) коллекциями, а также назначением методов `filter` и `map`.
