# Техническое задание: Сквозной проект (Спринты 1–3)

## Разработка комплексного консольного движка Pokémon TCG

---

### 1. Контекст и архитектурная цель

Сквозной проект представляет собой поэтапную сборку базового движка для моделирования игровой сессии **Pokémon TCG**. Проект объединяет три последовательных этапа разработки (Спринта):

1. **Спринт № 1:** Оцифровка структуры данных карты Тренера.


2. **Спринт № 2:** Моделирование состояния игрового стола, работа с динамическими счетчиками ресурсов и кастинг типов.


3. **Спринт № 3:** Реализация движка правил, условных проверок (`if-else`, `when`) и вычисление статуса боя.

Итоговая программа представляет собой единый исполняемый пайплайн (`Main.kt`), выполняющий пошаговую обработку пользовательского ввода, валидацию ресурсов, расчет урона с учетом элементальной уязвимости и формирование консольного отчета.

---

### 2. Спецификация данных (Data Model)

#### **2.1. Входные текстовые параметры (Считываются через `readln()`)**

* **Свойства карты (Спринт № 1):** `cardTypeInput`, `cardSubtypeInput`, `cardNameInput`, `effectTextInput`, `ruleTextInput`, `illustratorInput`.


* **Параметры состояния и боя (Спринты № 2–3):**
* `deckSizeInput` (`String`) — начальный размер колоды.


* `energyOnBoardInput` (`String`) — доступный запас энергии на столе.


* `discardEnergyCostInput` (`String`) — стоимость сброса энергии для атаки.


* `baseDamageInput` (`String`) — базовый урон атаки.
* `attackerElementInput` (`String`) — стихия атакующего Покемона (`"Fire"`, `"Water"`, `"Grass"`).
* `defenderElementInput` (`String`) — стихия защищающегося Покемона (`"Fire"`, `"Water"`, `"Grass"`).
* `defenderHpInput` (`String`) — текущее HP противника до атаки.



#### **2.2. Приведенные числовые параметры и свойства**

* `healAmount` (`Int = 60`), `cardNumber` (`Int = 105`), `totalInSet` (`Int = 106`) — характеристики карты (Спринт № 1).


* `deckSize` (`Int`) — `deckSizeInput.toInt()`.


* `energyOnBoard` (`Int`) — `energyOnBoardInput.toInt()`.


* `discardEnergyCost` (`Int`) — `discardEnergyCostInput.toInt()`.


* `baseDamage` (`Int`) — `baseDamageInput.toInt()`.
* `defenderHp` (`Int`) — `defenderHpInput.toInt()`.

#### **2.3. Динамические переменные состояния и вычисляемые показатели**

* `cardsInHand` (`Int`, `var`) — количество карт в руке (начальное значение: `7`).


* `discardPileSize` (`Int`, `var`) — количество карт в сбросе (начальное значение: `0`).


* `isAttackAllowed` (`Boolean`, `var`) — флаг валидации достаточности энергии.
* `weaknessMultiplier` (`Double`, `val`) — коэффициент уязвимости по стихиям (`1.0`, `1.2`, `1.5`, `2.0`).
* `finalDamage` (`Double`, `val`) — итоговый урон (`baseDamage * weaknessMultiplier`).
* `remainingHp` (`Int`, `val`) — остаток HP противника после атаки (не менее `0`).
* `matchStatus` (`String`, `val`) — вердикт по состоянию противника после атаки.

### 3. Требования к алгоритму и логике работы

Программа `Main.kt` должна выполнять следующую цепочку действий:

#### **Блок 1. Оцифровка карты и инициализация (Спринт № 1)**

1. Запросить у пользователя с помощью `print()` текстовые характеристики карты Тренера (`cardType`, `cardSubtype`, `cardName`, `effectText`, `ruleText`, `illustrator`).


2. Инициализировать константы `healAmount` (60), `cardNumber` (105), `totalInSet` (106).


3. Форматированно вывести карточку в консоль согласно эталонному макету (со сплошными разделителями и интерполяцией строк `$`).



#### **Блок 2. Считывание параметров стола и манипуляция счетчиками (Спринт № 2)**

1. Запросить `deckSizeInput` и `energyOnBoardInput`, привести к `Int` с помощью `.toInt()`.


2. Промоделировать розыгрыш карты предмета: декрементировать `cardsInHand--` и инкрементировать `discardPileSize++`.


3. Запросить `discardEnergyCostInput`, привести к `Int` и прибавить к сбросу с помощью составного присваивания `discardPileSize += discardEnergyCost`.



#### **Блок 3. Проверка правил, расчет урона и состояния (Спринт № 3)**

1. **Валидация ресурсов (Классический `if-else`):**
* Если `energyOnBoard >= discardEnergyCost` — установить `isAttackAllowed = true` и вывести лог успешной проверки.
* Иначе — установить `isAttackAllowed = false`, вывести сообщение об ошибке и завершить выполнение атаки.


2. **Ввод параметров боя:** При успешной валидации запросить `baseDamageInput`, `attackerElementInput`, `defenderElementInput`, `defenderHpInput` и кастить числовые значения.
3. **Расчет уязвимости (`when` Expression с блоками `{ }`):**
* `"Water"` против `"Fire"` $\rightarrow$ вывод лога эффекта, возврат `2.0`.
* `"Fire"` против `"Grass"` $\rightarrow$ вывод лога эффекта, возврат `1.5`.
* `"Grass"` против `"Water"` $\rightarrow$ вывод лога эффекта, возврат `1.2`.
* Во всех остальных случаях $\rightarrow$ вывод лога базового урона, возврат `1.0`.


4. **Математический расчет и завершение хода:**
* Рассчитать `finalDamage = baseDamage * weaknessMultiplier`.
* Вычислить остаток HP с защитой от отрицательных значений через выражение `if-else`: `if (calculatedHp < 0) 0 else calculatedHp`.
* Промоделировать конец хода: декрементировать колоду `deckSize--`, инкрементировать руку `cardsInHand++` и вычислить остаток от деления `deckSize % 2`.




5. **Определение статуса боя (Безаргументное выражение `when`):**
* `remainingHp == 0` $\rightarrow$ `"ПОКЕМОН НОКАУТИРОВАН! Возьмите призовую карту (Prize Card)."`.
* `remainingHp in 1..30` $\rightarrow$ `"КРИТИЧЕСКОЕ СОСТОЯНИЕ! Противник на грани нокаута."`.
* Иначе $\rightarrow$ `"БОЙ ПРОДОЛЖАЕТСЯ. Противник сохраняет боеспособность."`.



#### **Блок 4. Итоговый отчет**

Вывести сводный консольный лог состояния игрового стола, содержащий обновленные значения всех счетчиков и итоговый статус.

### 5. Критерии оценки (3-балльная шкала)

#### **Оценка «5» (Отлично)**

* Все 3 модуля сквозного проекта интегрированы в единую рабочую программу без синтаксических ошибок.
* Приглашения к вводу выполнены через `print()`.


* Все вводимые строки, участвующие в вычислениях, явно приведены к числовым типам через `.toInt()`.


* Динамические счетчики (`cardsInHand`, `discardPileSize`, `deckSize`) изменяются с помощью операторов `++`, `--`, `+=`.


* Корректно разделены классический `if-else` (для логики валидации энергии) и выражения `when` / `if` (с присвоением результата напрямую в `val`).
* В выражениях `when` с многострочными блоками `{ }` верно возвращается последнее значение блока.
* Для определения `matchStatus` применен безаргументный `when` с диапазоном `in 1..30`.
* Вывод полностью структурирован и отформатирован шаблонами строк `$`.

#### **Оценка «4» (Хорошо)**

* Код компилируется и правильно выполняет математические и логические операции.
* Присутствуют недочеты:
* Для ввода использован `println()` вместо `print()`.


* Вместо синтаксиса выражений (`val x = when (...)`) применен классический подход с мутабельными переменными (`var x; when (...)`).
* Вместо унарных операторов (`++`, `--`) применены обычные бинарные операции (`x = x + 1`).





#### **Оценка «3» (Удовлетворительно)**

* Программа запускается, но логика нарушена:
* Отсутствует обязательный блок `else` в выражениях `when` / `if`.
* Не выполняется кастинг типов, часть числовых параметров хранится как `String`.


* Нарушена связность модулей (например, значения счетчиков «зашиты» константами).



#### **Оценка «2» / Не зачтено**

* Программа не компилируется или студент не может объяснить принципы кастинга типов и работы условных операторов.
