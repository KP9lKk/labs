## Техническое задание: Расширение игрового цикла дуэли Pokémon TCG (Модуль: Коллекции данных)## 1. Контекст и интеграция со Stage 3
В рамках данной лабораторной работы производится развитие и надстройка над кодом из Stage 3 (где был реализован пошаговый боевой цикл while между игроком и базовым противником).
Главная цель — внедрить в готовую архитектуру боя структуры данных для хранения множества объектов: массивы фиксированной длины и динамические списки List<T>. Поведение дуэли усложняется: теперь игрок управляет не одной жесткой атакой, а выбирает приемы из массива доступных скиллов, а перед боем может использовать расходники из динамического инвентаря.
------------------------------
## 2. Переменные и новые структуры данных## 2.1. Дополнения к переменным Игрока
Вместо одиночных переменных attack1Name и attack2Name вводится фиксированный массив:

* skills (string[]) — массив доступных атак покемона, строго на 3 элемента.
* backpack (List<string>) — динамический список (сумка тренера) для хранения предметов поддержки. Изначально заполняется 3 предметами: "Зелье HP (+30)", "Стимулятор урона (+10)", "Антидот".

## 2.2. Модификация параметров Боя

* inventoryChoice (int) — выбор действия в инвентаре перед боем.
* damageBonus (int) — временный бонус к урону игрока (начальное значение 0, увеличивается при использовании предметов).

------------------------------
## 3. Порядок выполнения и архитектура программы## ЭТАП 1: Инициализация массива атак и динамического инвентаря (Ввод данных)

1. Объявить массив skills на 3 элемента. Запросить у пользователя ввод названий трех атак для его покемона через цикл for.
2. Объявить динамический список строк backpack и сразу добавить туда три базовых предмета ("Зелье HP (+30)", "Стимулятор урона (+10)", "Антидот") с помощью метода .Add().

## ЭТАП 2: Интерактивная подготовка к бою (Работа с List<T>)
Перед запуском предстартового отсчета из Stage 3, тренеру дается возможность заглянуть в сумку:

1. Вывести на экран заголовок "=== ПОДГОТОВКА К БОЮ: ИНВЕНТАРЬ ===".
2. С помощью цикла foreach последовательно вывести все предметы, лежащие в backpack.
3. Запросить у пользователя выбор: "Хотите использовать предмет? (1 - Да, 0 - Начать бой сразу)".
4. Если пользователь выбирает 1:
* Вывести список предметов с их порядковыми номерами (индексами).
    * Запросить индекс предмета для применения через int.Parse(Console.ReadLine()).
    * С помощью конструкции switch или if/else обработать эффект выбранного предмета:
    * Если выбрано "Зелье HP (+30)": увеличить текущее hp покемона игрока на 30.
        * Если выбрано "Стимулятор урона (+10)": установить переменную damageBonus = 10.
        * Если выбран другой предмет: вывести сообщение "Этот предмет сейчас бесполезен!".
    * Обязательно удалить использованный предмет из списка backpack с помощью метода .Remove() или .RemoveAt().
    * Вывести в консоль обновленное количество предметов в сумке через свойство backpack.Count.

## ЭТАП 3: Модифицированный цикл пошаговой дуэли (Работа с массивом)
Интегрировать массив атак в главный боевой цикл while (hp > 0 && enemyHp > 0) из Stage 3:

1. В начале каждого раунда при запросе действия игрока выводить не жесткий текст, а динамически сформированное меню на основе массива skills.
2. Валидация выбора действия (цикл do-while) теперь должна проверять, что пользователь ввел число от 1 до 3 (так как атак три).
3. При расчете хода игрока:
* Извлечь название выбранной атаки из массива по формуле: skills[actionChoice - 1].
    * К итоговому урону, который наносится противнику enemyHp, автоматически прибавлять значение damageBonus (если ранее был использован стимулятор). После первой же атаки damageBonus сбрасывается в 0.
    * Вывести строчку реакции боя с подстановкой конкретного имени атаки из массива.

## 5. Критерии оценки лабораторной работы## Оценка «5» (Отлично)

* Программа представляет собой сквозное решение, полностью сохранившее логику Stage 3, но успешно расширенное коллекциями.
* Массив атак skills объявлен строго с фиксированной длиной (3 элемента) и заполняется строго в цикле.
* Динамический список backpack корректно инициализируется, перебирается через foreach, а выбранный элемент бесследно удаляется из коллекции методами List.
* Выбор атаки в бою завязан на чтение элементов массива по динамическому индексу [actionChoice - 1].

## Оценка «4» (Хорошо)

* Код компилируется и выполняет дуэль, механика инвентаря и атак работает.
* Присутствуют некритичные архитектурные замечания:
* Список предметов перебирается обычным циклом for вместо обязательного по заданию foreach.
    * После применения предмета программист забыл вызвать метод .Remove(), и вещь остается в инвентаре.
    * Индексы массива зашиты в коде вручную (skills[0], skills[1]) вместо гибкой подстановки выбора пользователя.

## Оценка «3» (Удовлетворительно)

* Массив атак создан и заполняется, но в боевом цикле по-прежнему выводятся старые жестко зашитые текстовые названия из Stage 3.
* ИЛИ Механика инвентаря со списками List<T> вызывает падение программы из-за выхода за границы коллекции (ArgumentOutOfRangeException).
