# Техническое задание: Турнир Лиги Покемонов (Глобальный игровой цикл с коллекциями)

## 1. Контекст и связь с предыдущими частями
В рамках данной лабораторной работы производится финальный **рефакторинг, обобщение и масштабирование** кода из всех предыдущих этапов:
1. **Часть 1 (Оцифровка карточки):** Использование динамического ввода текстовых и числовых характеристик покемона.
2. **Часть 2 (Механика интерактивного боя):** Расчёт модификаторов урона (`if/else`, `switch`), обработка уязвимостей и устойчивостей.
3. **Часть 3 (Универсальный цикл дуэли):** Пошаговый бой внутри циклов, валидация пользовательского ввода и обработка статусов.

**Главное отличие и усложнение:** Мы полностью отказываемся от дуэли один на один. Теперь игрок формирует полноценную **команду из 3-х покемонов (массив)**, а также управляет динамическим **инвентарём расходных предметов (список `List<T>`)**. Вместо одного фиксированного врага игроку предстоит пройти **турнирную сетку из нескольких последовательных оппонентов**, эффективно распределяя ресурсы и переключая бойцов.

## 2. Переменные и структуры данных

### 2.1. Инвентарь и Команда Игрока (Динамические и фиксированные коллекции)
* `activeTeam` — одномерный массив строк (`string[]`) строго на **3 элемента** для хранения имён выбранных покемонов.
* `backpack` — динамический список строк (`List<string>`) для хранения предметов инвентаря.
* `pokedexHP` — массив целых чисел (`int[]`) на **3 элемента**, хранящий максимальное и текущее здоровье каждого из 3 покемонов игрока (индексы строго соответствуют массиву `activeTeam`).
* `pokedexDamage` — массив целых чисел (`int[]`) на **3 элемента**, хранящий базовый урон основных атак покемонов.

### 2.2. База данных Турнира (Задаётся жестко в коде программы)
Вместо одного врага создаются параллельные массивы (или списки) для **3-х последовательных боссов** турнира:
* `enemyNames` (`string[]`) — `{"Мяут", "Геодуд", "Гарчомп"}`.
* `enemyHPs` (`int[]`) — `{40, 65, 90}`.
* `enemyDamages` (`int[]`) — `{10, 15, 25}`.
* `enemyTypes` (`int[]`) — `{3, 1, 2}` (где `1` — Боевой, `2` — Стальной, `3` — Обычный тип для расчёта уязвимостей игрока).

### 2.3. Системные параметры
* `currentEnemyIndex` (`int`) — индекс текущего соперника на турнире (от 0 до 2).
* `activeFighterIndex` (`int`) — индекс покемона игрока, который находится на арене прямо сейчас (от 0 до 2).

## 3. Порядок выполнения и архитектура программы

### ЭТАП 1: Подготовка к турниру (Работа с коллекциями)
1. **Сбор боевой команды (Массивы):** С помощью цикла `for` запросить у пользователя имена 3-х покемонов. Для каждого покемона также поочередно запросить его Очки Знаменитости/Здоровья (HP) и базовый урон. Записать данные в соответствующие массивы (`activeTeam`, `pokedexHP`, `pokedexDamage`).
2. **Снаряжение сумки (Списки `List<T>`):** Создать пустой список `backpack`. С помощью метода `.Add()` автоматически положить туда 3 предмета: `"Зелье HP"`, `"Суперзелье"`, `"Антидот"`. Вывести на экран общее количество предметов через свойство `.Count`.

### ЭТАП 2: Предстартовый отсчёт и аудит
1. Очистить экран (`Console.Clear()`).
2. Вывести красивый заголовок начала турнира и запустить цикл со счётчиком `for` для обратного отсчёта от 3 до 1 перед открытием ворот арены.

### ЭТАП 3: Глобальный турнирный цикл (Вложенные циклы `while` и `do-while`)
Главный цикл программы выполняется, пока жива команда игрока (хотя бы у одного покемона `HP > 0`) и не побеждены все 3 босса (`currentEnemyIndex < 3`).

Внутри глобального цикла для каждого босса запускается локальный пошаговый бой `while (pokedexHP[activeFighterIndex] > 0 && enemyHPs[currentEnemyIndex] > 0)`:

1. **Фаза Интерактивного Выбора (Цикл `do-while` для валидации):**
   Каждый раунд выводится меню доступных действий. Программа требует ввода числа от 1 до 3:
   * `1` — Атаковать текущим покемоном.
   * `2` — Использовать предмет из сумки.
   * `3` — Заменить активного покемона на другого из массива `activeTeam`.
2. **Выполнение действия Игрока (`switch` / `if-else`):**
   * **Если выбрана Атака (1):** Наносится урон из `pokedexDamage[activeFighterIndex]`. Дополнительно запрашивается проверка спецэффекта (критический удар: 1 — успех, 0 — промах). При успехе урон увеличивается на +15 единиц. Урон вычитается из здоровья текущего врага `enemyHPs[currentEnemyIndex]`.
   * **Если выбран Предмет (2):** Программа проверяет, не пуст ли список `backpack`. Если в сумке есть предметы, выводится их полный список через цикл `foreach` в формате `"[Индекс] Предмет -> {item}"`. Пользователь вводит имя или индекс предмета. При применении `"Зелье HP"` активный боец восстанавливает 30 HP. Использованный предмет строго удаляется из коллекции `backpack` через `.Remove()`.
   * **Если выбрана Замена (3):** Выводится список всей вашей команды с текущим здоровьем. Пользователь вводит индекс нового бойца (0, 1 или 2). Переменная `activeFighterIndex` обновляется. Ход переходит к врагу.
3. **Проверка нокаута врага:** Если здоровье босса `<= 0`, текущий бой завершается (`break`). Игроку начисляется победа в этапе, а индекс `currentEnemyIndex` увеличивается на 1.
4. **Ход Компьютера (Расчёт входящего урона):**
   Если враг выжил, он атакует. Программа анализирует тип врага (`enemyTypes`). На основе этого через оператор `switch` вычисляется финальный урон по active покемону игрока:
   * Если тип Боевой (`1`) — урон по игроку удваивается (эффект уязвимости).
   * Если тип Стальной (`2`) — урон снижается на 10 единиц (эффект устойчивости).
   * Если тип Обычный (`3`) — урон наносится без изменений.
5. **Проверка нокаута игрока:** Если `pokedexHP[activeFighterIndex] <= 0`, этот покемон объявляется недееспособным. Программа автоматически принуждает игрока выбрать другого живого покемона из массива через меню замены. Если живых покемонов не осталось — весь турнирный цикл прерывается (`break`).

## 5. Критерии оценки (3-балльная шкала)

### Оценка «5» (Отлично)
* Программа успешно объединяет в себе массивы (`string[]`, `int[]`) и динамические списки (`List<string>`) для организации полноценного менеджмента команды и инвентаря.
* Корректно применены и скомбинированы все три типа циклов: `for` (регистрация и отсчёт), `while` (игровые раунды) и `do-while` (строгая проверка корректности ввода команд меню).
* Реализован последовательный перебор сумки через цикл `foreach`. Применение предмета динамически уменьшает размер коллекции с помощью `.Remove()`.
* Архитектура вычислений (уязвимости типов через `switch` и модификаторы критических попаданий) работает без логических и математических ошибок.

### Оценка «4» (Хорошо)
* Логика турнира работает, программа компилируется.
* Допущены небольшие недочёты: перебор предметов в сумке выполнен через стандартный `for` вместо `foreach`, либо при удалении предмета происходят сбои индексов.
* Нарушена структура пошаговой логики (например, погибший босс успевает нанести урон игроку перед завершением цикла).

### Оценка «3» (Удовлетворительно)
* Программа запускается, но логика турнира урезана: вместо 3-х последовательных врагов реализован бой только с одним соперником.
* Коллекции применены формально (например, массив команды создан, но переключение между покемонами в коде не работает или приводит к вылету).
