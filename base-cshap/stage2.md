# Техническое задание: Интерактивная механика карточки Pokémon TCG

## 1. Контекст и связь с первой частью

В рамках данной работы продолжается оцифровка карточки Пикачу (№ 025). Текстовые данные считываются от пользователя, а числовые характеристики и логика взаимодействия с карточкой обрабатываются с помощью преобразования типов (`int.Parse`), условных операторов (`if / else`) и конструкции `switch`.

---

## 2. Переменные и входные данные

### 2.1. Строковые данные (Вводятся пользователем через `Console.ReadLine()`)

* `name` (`string`) — имя покемона (`"Пикачу"`).
* `attack1Name` (`string`) — название первой атаки (`"Электроудар"`).
* `attack2Name` (`string`) — название второй атаки (`"Быстрая Атака"`).

### 2.2. Числовые параметры (Считываются и преобразуются через `int.Parse`)

* `hp` (`int`) — очки здоровья (например, `60`).
* `attack2BaseDamage` (`int`) — базовый урон второй атаки (например, `20`).
* `incomingDamage` (`int`) — базовый урон входящей атаки противника.

---

## 3. Порядок выполнения работы

### БЛОК 1: Преобразование типов и динамический расчёт (`int.Parse`)

1. Запросить у пользователя базовые числовые показатели карточки через `Console.Write()`:
* Текущее количество **HP** покемона.
* Базовый урон атаки **«Быстрая Атака»**.


2. Преобразовать полученные строки в тип `int` с помощью `int.Parse()`.

### БЛОК 2: Логика атак и уязвимостей (`if / else` и `switch`)

#### Модуль 1. Эффект первой атаки «Электроудар» (`if / else`)

1. Запросить результат броска монеты (`1` — Орёл, `0` — Решка).
2. С помощью условного оператора `if / else` определить эффект и вывести соответствующую строчку реакции:
* При `1` (Орёл): `"Результат: Активный Покемон противника парализован!"`
* При `0` (Решка): `"Результат: Эффект паралича не сработал."`



#### Модуль 2. Эффект второй атаки «Быстрая Атака» (`if / else`)

1. Запросить результат броска монеты (`1` — Орёл, `0` — Решка).
2. С помощью `if / else` рассчитать итоговый урон и вывести результат с подстановкой соответствующей переменной урона:
* При `1` (Орёл): к `attack2BaseDamage` прибавляется **+10** единиц урона.
*Строчка реакции:* `"Результат: Выпал орёл! Итоговый урон: "`
* При `0` (Решка): урон остаётся базовым.
*Строчка реакции:* `"Результат: Выпала решка! Итоговый урон: "`



#### Модуль 3. Расчёт входящего урона с учётом свойств карточки (`switch` и `if / else`)

1. Запросить у пользователя базовый урон входящей атаки противника (`int.Parse`).
2. Вывести меню выбора типа входящей атаки:
* `1` — Боевой тип (Weakness: x2)
* `2` — Стальной тип (Resistance: -20)
* `3` — Обычный тип (Без изменений)


3. С помощью конструкции `switch` рассчитать итоговый полученный урон (`finalIncomingDamage`) и вывести строчку реакции:
* Для `1` (Боевой тип): урон удваивается ($\text{Урон} \times 2$).
*Строчка реакции:* `"Расчёт: Боевой тип! Урон удваивается (x2)."`
* Для `2` (Стальной тип): урон уменьшается на 20 единиц ($\text{Урон} - 20$, но не меньше 0).
*Строчка реакции:* `"Расчёт: Стальной тип! Урон уменьшается на 20 (Resistance: -20)."`
* Для `3` (Обычный тип): урон наносится без изменений.
*Строчка реакции:* `"Расчёт: Обычный тип! Урон наносится без изменений."`
* Для `default` (некорректный ввод):
*Строчка реакции:* `"Ошибка: Выбран неизвестный тип атаки!"`


4. Вывести итоговый урон с подстановкой переменной: `"Получено урона: "`.
5. Вычесть полученный урон из `hp` и с помощью `if / else` выдать статус покемона:
* Если `hp <= 0`: `"Пикачу нокаутирован!"`
* Если `hp > 0`: `"Пикачу выдержал удар! Остаток HP: "` *(с подстановкой переменной `hp`)*

## 5. Критерии оценки (3-балльная шкала)

### Оценка «5» (Отлично)

* Ввод всех числовых параметров реализован через `int.Parse()`.
* Все три игровых модуля (две атаки и расчёт входящего урона) работают корректно.
* Конструкция `switch` и условные операторы `if / else` применены без логических ошибок.
* Все строчки реакций точно соответствуют техническому заданию, а значения вычисляемых переменных подставляются корректно.
* Вывод аккуратно отформатирован.

### Оценка «4» (Хорошо)

* Код компилируется и выполняет все требуемые расчёты.
* Присутствуют некритичные недочёты:
* Не учтено ограничение, чтобы полученный урон при резисте не уходил в отрицательные значения.
* В `switch` отсутствует ветка `default` или пропущена одна из строчек реакции.
* Использованы неинформативные имена переменных (`a`, `b`, `x`).



### Оценка «3» (Удовлетворительно)

* Программа запускается, но реализован только Блок 1 и один из модулей Блока 2.
* **ИЛИ** Преобразование типов выполнено с ошибками, приводящими к сбоям во время выполнения.

### Оценка «2» / Не зачтено

* Программа не компилируется.
* Студент не может объяснить работу использованных условных операторов и метода `int.Parse`.
